# GAFIME v0.4.7 ROCm Native Backend Notes

This document tracks the ROCm/HIP backend development work for v0.4.7.
It is implementation evidence, not a release publication checklist.

## Scope

Implemented local development scope:

- Native HIP shared library: `libgafime_rocm.so`.
- Python backend wrapper: `gafime.backends.native_rocm_backend.NativeRocmBackend`.
- Explicit backend names: `backend="rocm"` and `backend="hip"`.
- Continuous global matrix batch scoring with homogeneous arity templates
  `1..5`.
- Local bucket batch scoring for explicit candidate families such as
  time-series transforms.
- Soft discrete feature scoring.
- Adaptive soft-binary discrete selector scoring.
- AMD platform capability reporting through HIP runtime properties.
- GPU hard discrete mode rejection using the same rule as CUDA/Metal:
  `GPU feature engineering with discrete hard mode is not supported!`

Not finalized in this phase:

- Distribution wheels and release publishing.
- ROCm cloud runner benchmarking.
- AMD product-family profiling claims.

Distribution policy for v0.4.7:

- `gafime` remains the stable Python/Core package.
- `gafime-cuda` carries the CUDA native payload.
- `gafime-rocm` carries the ROCm/HIP native payload for Linux x86_64.
- `gafime[cuda]` and `gafime[rocm]` are convenience extras that install the
  matching vendor payload when those packages are published.
- Windows ROCm payload wheels are not shipped in v0.4.7. Use C++ Core on
  Windows AMD systems for this release. The current `bundled` staged-wheel
  policy is Linux x86_64 only.

Backend priority for ROCm payload installs:

```text
rocm -> core
```

Use `backend="rocm"` or `backend="hip"` to force ROCm explicitly.

## Build Controls

Local ROCm builds use `hipcc`:

```bash
uv pip install -e .
python .github/scripts/stage_gpu_payload.py rocm payload-src/gafime-rocm \
  --rocm-wheel-policy bundled
GAFIME_ROCM_ARCHS=<rocm-offload-target> uv pip install -e payload-src/gafime-rocm --no-build-isolation
```

Relevant environment variables:

- `GAFIME_ROCM_ARCHS=<rocm-offload-target>[,<rocm-offload-target>...]`:
  explicit HIP offload targets.
- Missing `hipcc` fails the `gafime-rocm` payload build.

If `GAFIME_ROCM_ARCHS` is not set, setup tries `rocm_agent_enumerator`. If it
cannot detect a target, the payload build fails with a clear error instead of
guessing a device-specific architecture.

## Backend Behavior

ROCm report metric policy mirrors CUDA for v0.4.7 development:

- stats-backed GPU metrics: `pearson`, `r2`
- accepted report metrics: `pearson`, `spearman`, `mutual_info`, `r2`
- missing report metrics are completed through the native metric scorer where
  needed

Discrete GPU paths are soft/vectorized only. Hard threshold mode is not a ROCm
GPU path.

ROCm backend instances expose `NativeRocmBackend.platform_info`, which reports
raw HIP runtime capabilities:

- `device_kind`: `integrated_gpu` or `discrete_gpu`, from HIP's `integrated`
  flag only
- `runtime_arch_name`: the exact target string reported by ROCm, preserved as
  diagnostics/build metadata only
- `memory_policy`: `shared_system_memory`, `integrated_device_memory`, or
  `device_memory`
- HIP capability flags such as managed memory, pageable host tables,
  host-register support, memory-pool support, large-BAR status, CU count, L2,
  and wavefront size

For shared-system-memory integrated GPUs, broad continuous matrix scans and
local bucket/time-series scans request the UMA host-mapped input mode. Native
HIP code performs page-aware `hipHostRegister(..., hipHostRegisterMapped)` and
launches kernels against mapped host pointers. If ROCm rejects a specific
registration, that buffer falls back to the resident `hipMalloc` + copy path.

Local iGPU validation after the page-aware registration fix:

```text
requested_memory_mode uma_host_mapped
continuous_input_mode uma_host_mapped
bucket_input_mode uma_host_mapped
```

Discrete one-shot ROCm scoring still uses temporary resident HIP allocations.
GAFIME does not classify AMD GPUs by product name or by interpreting ROCm
offload-target suffixes.
