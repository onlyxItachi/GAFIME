# GAFIME v0.4.0 Discrete Function Engine Notes

This document records the v0.4.0 engine-level discrete function feature family.
It is local release documentation for maintainers and agents.

## Public API

Discrete function search is part of the existing `GafimeEngine`; it is not a
separate package.

```python
from gafime import ComputeBudget, EngineConfig, GafimeEngine

config = EngineConfig(
    metric_names=("pearson",),
    enable_discrete_functions=True,
    discrete_mode="soft",
    discrete_ranking="split_aware",
    discrete_threshold_source="quantile",
    discrete_gate_sharpness=12.0,
    budget=ComputeBudget(
        max_comb_size=2,
        max_discrete_candidates=100_000,
        max_thresholds_per_feature=9,
        max_intervals_per_feature=12,
        max_feature_pairs_for_rectangles=500,
        top_k_features_for_discrete=50,
    ),
)

report = GafimeEngine(config).analyze(X, y, feature_names=feature_names)
```

Discrete candidates use the same `EngineConfig.metric_names` as continuous
interactions for reported metrics. There is no separate discrete metric
parameter in v0.4.0.

`EngineConfig.discrete_ranking` controls how discrete candidates are ordered in
the report:

- `"split_aware"` (default): rank with mask mutual information, soft
  variance/impurity reduction, and residual gain scores.
- `"metric"`: rank by the selected report metrics in `metric_names`.
- `"none"`: preserve candidate planning order.

## Candidate Families

The implemented family names are:

- `discrete_function_soft_threshold`
- `discrete_function_soft_interval`
- `discrete_function_value_gated_threshold`
- `discrete_function_soft_rectangle`
- `discrete_function_value_in_soft_rectangle`

Thresholds are fixed engine-generated candidates. v0.4.0 uses quantile
thresholds only:

```python
(0.05, 0.10, 0.25, 0.40, 0.50, 0.65, 0.75, 0.90, 0.95)
```

Tree-inspired thresholds and learnable threshold refinement are intentionally
out of scope for this engine release.

## Backend Rules

CUDA and other GPU backends support only soft, vectorized discrete functions.
Hard discrete mode is rejected on GPU with:

```text
GPU feature engineering with discrete hard mode is not supported!
```

CPU and NumPy may evaluate hard mode using vectorized host comparisons. Metal
soft mode has a native path when the Metal library is built; Metal hard mode
uses the same GPU hard-mode rejection unless a CPU-side fallback is explicitly
implemented later.

## GPU Selection Metrics

Discrete report metrics still follow `EngineConfig.metric_names`, but default
discrete candidate ranking is not Pearson-only.

The CUDA backend now has a native soft-discrete selection scoring API:

- binned mutual information between the split mask and target,
- soft variance/impurity reduction,
- residual absolute correlation against a baseline residual,
- residual R2 gain against a baseline residual.

This path is exposed through:

```python
backend.score_discrete_selection_candidates(
    X_train,
    y_train,
    candidates,
    baseline_pred=baseline_pred_train,
    mi_bins=16,
)
```

On CUDA this uses `gafime_discrete_selection_batch_cuda`. CPU/NumPy use the
same Python reference scoring. Spearman remains a report metric/fallback path;
it is not part of the native CUDA selector because rank transforms require
sort/segmented-rank machinery that is different from the fused map-reduce
kernels used here.

## Rust Helper Import

Use the package alias:

```python
from gafime import subfunctions
```

Prefer this over direct user-facing `import gafime_cpu`. The Rust extension
name remains an implementation detail.

## Cache-Local Launch Ordering

The Rust `BatchScheduler` now exposes cache-local equation ordering:

```python
from gafime import subfunctions

scheduler = subfunctions.BatchScheduler(max_blocks=1024)
order = scheduler.order_equations([[1, 2], [1, 3], [8, 9]])
batches = scheduler.create_equation_batches([[1, 2], [1, 3], [8, 9]])
```

This is launch ordering only. GAFIME does not reserve, partition, or pin CUDA
L2 cache. The CUDA code does not use `cudaLimitPersistingL2CacheSize`,
`cudaStreamAttributeAccessPolicyWindow`, or `cudaCtxResetPersistingL2Cache`.

Nsight Compute on the discrete CUDA soft kernel showed the locality change
materially improved the launch:

- duration: `4.93 ms`, down from `8.95 ms`
- DRAM throughput: `3.05%`, down from `81.83%`
- L2 hit rate: `98.45%`, up from `46.31%`
- registers/thread: `39`
- spills: `0`
- branch efficiency: `100%`
- achieved occupancy: `95.30%`

The remaining memory note is coalescing: NCU reported average global-load sector
use of about `23.8 / 32 bytes`.

## Benchmark And Profiling Commands

Local tests:

```bash
PYO3_PYTHON="$PWD/.venv/bin/python" cargo test --manifest-path src/cpu/gafime_cpu/Cargo.toml
.venv/bin/python -m pytest -q
```

Discrete application benchmark:

```bash
.venv/bin/python tests/benchmark_discrete_v040.py
```

CUDA NCU profile for the discrete soft kernel:

```bash
/usr/local/cuda-13.2/bin/ncu \
  --target-processes all \
  --set full \
  --kernel-name gafime_discrete_soft_batch_kernel \
  --launch-skip 1 \
  --launch-count 1 \
  --force-overwrite \
  --export /tmp/gafime_discrete_cacheaware_ncu \
  .venv/bin/python tests/profile_discrete_cuda_ncu.py \
  --samples 180000 \
  --features 64 \
  --candidates 8192 \
  --repeats 2
```

Build and release wheel steps remain gated by maintainer approval.
