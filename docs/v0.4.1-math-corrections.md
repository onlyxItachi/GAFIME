# GAFIME v0.4.1 Math Corrections

v0.4.1 fixes mutual-information scoring and discrete selector ranking without
changing the public engine API.

## Adaptive MI

`EngineConfig.mi_bins` is now an adaptive maximum. The default is `96`, but the
engine chooses the actual bin count from:

```text
2, 4, 8, 16, 32, 64, 96
```

For general report metrics, GAFIME uses adaptive dense quantile/rank bins and a
finite-sample bias correction. This prevents the fixed-bin estimator from
overstating MI on small datasets or underrepresenting larger datasets.

## Discrete Selector MI

Discrete split-aware ranking no longer bins the mask as a dense continuous
axis. Instead, it uses soft-binary MI:

```text
inside[target_bin]  += mask
outside[target_bin] += 1 - mask
```

This matches threshold, interval, and rectangle semantics: the candidate is an
inside/outside region, not an arbitrary continuous feature. It also keeps the
GPU selector small enough for shared-memory execution with target-bin template
capacities up to 96.

## CUDA MI Templates

The native CUDA selector uses `gafime_discrete_selection_adaptive_cuda`.
The Python frontend computes train-only adaptive target bins, maps the actual
bin count to a compile-time MI template capacity in:

```text
2, 4, 8, 16, 32, 64, 96
```

Rust `BatchScheduler.create_template_batches` then groups candidate
launches by that execution template before CUDA dispatch. The CUDA host code
uses a direct `switch` over the batch template and launches the corresponding
`gafime_discrete_selection_adaptive_kernel<BINS>` instantiation. Inside the
kernel, MI histogram loops run over the template constant so the compiler can
unroll/static-shape the shared-memory path.

## Support Guards

Selector MI and variance-reduction scores are set to zero when a mask has too
little effective support on either side:

```text
n_eff_inside  = sum(w)^2 / sum(w^2)
n_eff_outside = sum(1-w)^2 / sum((1-w)^2)
```

The support floor is adaptive:

```text
min_support = min(8.0, max(3.0, 0.02 * n_samples))
```

This keeps the medium/large-dataset protection against tiny accidental regions,
while avoiding over-pruning true narrow regions in small datasets. The same rule
is mirrored in the CUDA adaptive selector kernel.

## Backend Behavior

- Python/NumPy selector path uses the corrected soft-binary MI.
- C++ Core report metrics use adaptive dense MI.
- CUDA native selector uses `gafime_discrete_selection_adaptive_cuda` with
  homogeneous Rust template batches.
- If an older CUDA library is loaded, Python falls back to the corrected
  selector instead of using the older fixed `16x16` CUDA selector.
- Metal still uses the existing soft discrete feature kernel and falls back to
  Python for selector scoring.

## Validation Commands

Use local source builds only:

```bash
PYO3_PYTHON=/path/to/python3.12 python setup.py build_ext --inplace
python -m pytest tests/test_discrete_selection_scores.py tests/test_discrete_functions.py tests/test_discrete_native_gpu.py -q
python -m pytest -q
cargo test --manifest-path src/cpu/gafime_cpu/Cargo.toml
git diff --check
python -m build
```

Before publishing, install the locally built wheel in a fresh environment and
confirm that `gafime.__version__ == "0.4.1"` and CUDA discrete selection uses
the adaptive native selector when available.

See `docs/v0.4.1-edge-validation-log.md` for the iterative edge-case stress
log, including sklearn comparisons, CUDA template parity, and underpowered
small-sample diagnostics. The log also records sklearn/manual equivalence
checks for variance reduction, residual R2, public R2, Ridge CV gain ranking,
and GBM CV gain ranking.
