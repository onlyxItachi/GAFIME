# GAFIME v0.4.0 Wheel Build Readiness Notes

Local review date: 2026-05-17

These notes record the recurring wheel/distribution failure classes observed
from the repository's historical CI-fix commits and the current workflow. Exact
GitHub Actions logs were not available from this machine because `gh` was not
authenticated, so this document avoids claiming line-level log evidence.

## Previous Failure Classes

- **CUDA toolkit/action mismatch:** previous workflow fixes upgraded the pinned
  CUDA setup action for CUDA 13.x support. v0.4.0 keeps the pinned action and
  updates the requested toolkit to CUDA 13.2.0.
- **Unsupported CUDA architectures:** Volta/`compute_70` previously broke newer
  CUDA builds. v0.4.0 keeps the supported GPU policy at Turing and newer:
  `sm_75`, `sm_80`, `sm_86`, `sm_89`, `sm_90`, `sm_100`, `sm_120`, plus
  `compute_120` PTX fallback.
- **manylinux CUDA setup fragility:** relying on `dnf config-manager` can fail
  if the plugin is unavailable in the container. v0.4.0 writes the NVIDIA RHEL
  8 repo file directly, imports the NVIDIA key, installs CUDA 13.2 nvcc/cudart
  packages, and symlinks `/usr/local/cuda`.
- **PEP 517 isolated-build payload placement:** old builds wrote native
  artifacts into the source tree, which can leave wheels without native
  payloads for repair. The build now targets `self.build_lib` for isolated
  wheels and only writes into `gafime/` for in-place development builds.
- **manylinux Python development discovery:** full `Development` discovery can
  fail in portable manylinux images that omit `libpython`. The project keeps
  the module-oriented pybind/CMake path instead of requiring a full embedded
  Python development environment.
- **Python 3.14 / PyO3 compatibility:** Python 3.14 had previously been dropped
  while PyO3 support caught up. v0.4.0 restores cp314 wheel targeting and keeps
  the setup logic that bypasses strict PyO3 version checks for newer Python
  versions.
- **Windows encoding and export issues:** prior fixes removed non-ASCII setup
  output and added explicit CUDA DLL export flags. v0.4.0 keeps ASCII build
  logs and `-DGAFIME_BUILDING_DLL`.
- **Optional test dependencies:** CI wheel tests have failed when optional
  sklearn dependencies were missing. The workflow keeps `pytest scikit-learn`
  in `CIBW_TEST_REQUIRES`.
- **Trusted Publisher configuration:** PyPI publishing requires the `pypi`
  environment and id-token permission. v0.4.0 keeps publication gated to tag
  builds only.

## v0.4.0 Distribution Adjustments

- Workflow CUDA version is now CUDA Toolkit 13.2.0.
- Linux manylinux uses NVIDIA RHEL 8 packages:
  `cuda-nvcc-13-2` and `cuda-cudart-devel-13-2`.
- Windows uses CUDA Toolkit `13.2.0` and exports the `v13.2` toolkit path.
- `CIBW_BUILD` targets CPython 3.10, 3.11, 3.12, 3.13, and 3.14.
- `feature/**` pushes trigger wheel builds so release branches can validate
  artifacts before merge or tag publication.
- Build metadata uses SPDX-style `license = "Apache-2.0"` with `LICENSE`
  included as a license file.
