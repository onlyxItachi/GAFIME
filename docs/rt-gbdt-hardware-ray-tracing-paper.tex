\begin{abstract}
Tree ensembles and tree-derived decision-path features are among the most
effective tools for tabular learning, but large-scale candidate scoring remains
limited by candidate-row predicate evaluation, intermediate membership
materialization, and reduction of binary indicators against a target. This
paper describes an experimental CUDA backend primitive that maps bounded,
shallow gradient-boosted decision-tree (GBDT) path regions onto NVIDIA hardware
ray tracing using \optix. A decision path over one to three numerical features
is represented as an axis-aligned region, a tabular row is represented as a
point, and path membership becomes a point-containment query. The low-level ABI
keeps path descriptors compact and returns one result row per path with metric
columns. It is not yet the execution path of the public \gafime Python
decision-path adapter, which still expands membership before invoking the
generic continuous engine. The measurements therefore characterize a backend
primitive, not end-to-end GBDT training, inference, or public-API acceleration.

The main performance contribution is not faster materialization of a dense
row-by-path membership matrix. Instead, traversal results are reduced on device
into compact per-path statistics and exported through the experimental result
ABI. Traversal is hybrid: \optix performs BVH traversal and intersection work,
while programmable CUDA code performs exact guards, accumulation, and metric
finalization.
For tree-leaf-like batches whose regions are finite, bounded, two-dimensional,
and non-overlapping within each group, a first-hit traversal mode terminates
after the first exact in-region hit and fails closed if the non-overlap proof is
unavailable. On an RTX 4060 Laptop GPU, a $262{,}144 \times 8{,}192$ case takes
$56.109$ ms on the first call and $0.886$ ms at resident warm p50 over five
samples. The latter is $2.424$ trillion membership-equivalent evaluations/s,
but the end-to-end effective ray rate is $2.367$ billion rays/s over eight
groups; these are different denominators. Maximum absolute score difference is
$1.19209 \times 10^{-7}$ against an exhaustive CPU reference. A
$262{,}144 \times 1{,}048{,}576$ case takes $467.746$ ms first-call and
$20.180$ ms resident warm p50, or $13.621$ trillion
membership-equivalent evaluations/s and $0.104$ billion end-to-end effective
rays/s. A linear
partition oracle validates that larger result to $5.58794 \times 10^{-9}$.
These results identify a narrow systems primitive: bounded decision-path
scoring can benefit from BVH traversal and fused reduction when geometry is
tree-like and resident reuse is available.
\end{abstract}

\noindent\textbf{Keywords:}
GBDT systems; RT cores; OptiX; candidate scoring; fused reduction; tabular

\section{Introduction}

Gradient boosting decision trees are a standard workhorse for tabular machine
learning. Friedman formulated gradient boosting as greedy function
approximation \cite{friedman2001greedy}; XGBoost \cite{chen2016xgboost},
LightGBM \cite{ke2017lightgbm}, and CatBoost
\cite{prokhorenkova2018catboost} showed that practical performance depends as
much on systems decisions as on statistical modeling. Cache-aware layout,
sparsity handling, histogram construction, categorical encoding, and
parallelism choices decide whether a tree system scales.

This work targets a related but distinct problem: scoring very large numbers of
tree-derived decision-path candidates as explicit features. The intended
\gafime representation is a compact expression or path descriptor accompanied
by computed metrics, rather than a candidate-expanded vector. The experimental
CUDA ABI follows that representation. The current public Python decision-path
adapter does not: it materializes each membership vector and feeds an expanded
matrix to the generic continuous engine. This disclosure therefore isolates the
backend primitive and the integration contract that a future public path must
satisfy. The scale problem is candidate-row work, not ordinary matrix
multiplication.

A shallow decision path is a conjunction of threshold predicates. For example,
\[
  x_{f_0} > a \quad \wedge \quad x_{f_1} \le b .
\]
For one, two, or three participating features, this conjunction is naturally an
interval, rectangle, or box. Hardware ray tracing units are specialized to
traverse spatial acceleration structures and answer geometric intersection
queries at high throughput. NVIDIA \optix provides a programmable ray tracing
system for GPUs \cite{parker2010optix}, and RTX-class GPUs include dedicated
ray traversal and intersection hardware \cite{nvidia2018turing}. This suggests
the following mapping:
\[
  \text{row} \longrightarrow \text{point}, \qquad
  \text{decision path} \longrightarrow \text{bounded region}.
\]

The mapping is useful only if three engineering constraints hold. First, the
geometric result must preserve the original predicate semantics, including
strict and non-strict inequalities. Second, the output must remain compact; a
fast path that writes a dense membership matrix moves the bottleneck rather
than removing it. Third, backend ownership must remain explicit. In the target
architecture Rust owns candidate semantics, scheduling, and fallback policy;
\cuda executes only a validated request. The benchmark used here calls the
low-level C ABI directly and does not establish that this ownership path is
wired through the public API.

This paper is a technical disclosure of the \gafime v1 CUDA RT-core
implementation. It makes the following contributions:

\begin{enumerate}
  \item It formalizes a geometric mapping for finite, bounded,
  low-dimensional GBDT path regions.
  \item It describes an experimental CUDA C ABI that scores decision paths
  through \optix and exports one compact row per path with metric columns.
  \item It introduces a fail-closed first-hit mode for non-overlapping
  tree-leaf-like regions, together with the equivalence condition that makes
  first-hit traversal semantically valid.
  \item It reports first-call and resident warm performance on a laptop Ada
  GPU, with exhaustive and partition-oracle correctness checks, end-to-end
  effective ray rates, and membership-equivalent work rates reported separately.
\end{enumerate}

\section{Background and Related Work}

\subsection{GBDT Systems}

XGBoost combines gradient tree boosting with a sparsity-aware split finder,
weighted quantile sketching, and cache-conscious execution
\cite{chen2016xgboost}. LightGBM improves histogram-based training through
gradient-based one-side sampling and exclusive feature bundling
\cite{ke2017lightgbm}. CatBoost addresses target leakage and categorical
features through ordered boosting and specialized categorical handling
\cite{prokhorenkova2018catboost}. GPU-oriented tree systems such as
ThunderGBM \cite{wen2020thundergbm} and GPU histogram training work
\cite{zhang2017gputreeboosting} show that tree workloads can benefit from GPU
parallelism when memory access, histogram conflicts, and algorithm structure
are matched to the device.

The work here is not a replacement for these training systems. It focuses on
candidate scoring for decision-path-derived features. That distinction matters:
training chooses splits and updates an ensemble, while \gafime evaluates a
large candidate set and keeps compact scores. The relevant unit of work is a
membership-equivalent candidate-row evaluation rather than a tree-training
iteration.

\subsection{Tree Inference and Compilers}

Tree deployment systems such as Treelite \cite{cho2018treelite} and optimized
forest inference paths such as NVIDIA FIL \cite{nvidiafil} target fast
prediction for already-trained forests. Compiler approaches for tree inference,
including Treebeard \cite{vanessen2022treebeard}, lower tree traversal into
optimized code for a selected target. These systems optimize inference of model
outputs. \gafime instead scores candidate path features against a target and
therefore needs compact reductions over path membership rather than final
ensemble prediction alone.

\subsection{Ray Tracing Systems}

\optix is a general-purpose programmable ray tracing engine
\cite{parker2010optix}. Dedicated RTX hardware exposes fixed-function traversal
and intersection acceleration \cite{nvidia2018turing}. GPU ray traversal work
has studied how traversal efficiency depends on scheduling, memory locality,
divergence, and scene structure \cite{aila2009understanding,
aila2012understanding}. Embree \cite{wald2014embree} demonstrated that
carefully engineered ray traversal kernels can be useful reusable systems
infrastructure on CPUs. This paper applies ray traversal to a tabular
candidate-scoring problem: not rendering, but evaluating whether row-points
belong to many decision-path regions.

The closest methodological precedent is non-rendering use of RT hardware.
Zellmann et al. map scientific point-containment queries to zero-length rays
\cite{zellmann2022point}. RTIndeX maps point and range lookups to GPU ray
tracing \cite{henneberg2023rtindex}, RTXRMQ maps range-minimum queries to
closest-hit geometry \cite{meneses2023rtxrmq}, and RTScan maps conjunctive
database scans into balanced 3D ray-tracing jobs \cite{lv2024rtscan}. These
systems establish that a geometric reformulation can change both hardware use
and algorithmic work. They also motivate a skeptical baseline: RasterScan
retains a related grid data model but replaces BVH traversal and geometric
intersection with rasterization and arithmetic comparisons, outperforming its
RT-based database-indexing baselines in that domain \cite{doraiswamy2026raster}.
That result is not a direct measurement of decision-path scoring, but it shows
why comparisons against equally structure-aware non-RT algorithms are required.

\section{Decision Paths as Regions}

Let $X \in \R^{n \times d}$ be a tabular matrix with $n$ rows and $d$ features,
and let $y \in \R^n$ be a target. A path candidate $p$ is a conjunction of
threshold terms:
\[
  p = \{(f_\ell, s_\ell, t_\ell)\}_{\ell=1}^{L},
\]
where $f_\ell$ is a feature id, $s_\ell \in \{\le, >\}$ is the comparison, and
$t_\ell$ is a threshold. Membership for row $i$ is
\[
  z_{p,i} =
  \begin{cases}
    1, & \text{if all terms in } p \text{ hold for row } i,\\
    0, & \text{otherwise.}
  \end{cases}
\]

\begin{definition}[Representable RT path]
A path batch is representable by the current RT backend when every threshold is
finite and the entire resident feature matrix recorded at upload is finite. The
implementation stores one matrix-wide finiteness bit, so a NaN or infinity in
an unreferenced column still makes RT unsupported. A membership batch uses at
most three feature axes in total; compact scoring may split paths into internal
groups, each using at most three axes. Bounded two-dimensional groups may use
triangle geometry; one-dimensional, three-dimensional, or open-bound groups
require exact custom-AABB handling when supported.
\end{definition}

Each term tightens a lower or upper bound along a feature axis. For a path over
unique feature axes $(u_1,\ldots,u_k)$, $k \le 3$, the conjunction maps to
\[
  B_p = I_{p,1} \times \cdots \times I_{p,k},
\]
where $I_{p,j}$ may be lower-open or upper-closed depending on the original
predicate. A row maps to
\[
  q_i = (X_{i,u_1},\ldots,X_{i,u_k}).
\]
The desired semantic test is $z_{p,i}=1$ if and only if $q_i \in B_p$ under the
same open/closed comparison rules as the original path.

\section{Scoring Without Dense Membership}

The compact score path currently supports Pearson correlation and $R^2$ for
decision-path indicators. Non-finite targets are excluded from every statistic.
Let $V=\{i\mid y_i\text{ is finite}\}$ and $n_V=|V|$. For path $p$, define
\[
  S_x = \sum_{i\in V} z_{p,i}, \qquad
  S_y = \sum_{i\in V} y_i, \qquad
  S_{yy} = \sum_{i\in V} y_i^2, \qquad
  S_{xy} = \sum_{i\in V} z_{p,i}y_i .
\]
For $n_V>0$, the centered terms are
\[
  C_{xx}=S_x-\frac{S_x^2}{n_V},\qquad
  C_{yy}=S_{yy}-\frac{S_y^2}{n_V},\qquad
  C_{xy}=S_{xy}-\frac{S_xS_y}{n_V}.
\]
The Pearson score is
\[
  \rho_p =
  \begin{cases}
    \operatorname{clip}\left(C_{xy}/\sqrt{C_{xx}C_{yy}},-1,1\right),
      & C_{xx}C_{yy}>0,\\
    0, & \text{otherwise,}
  \end{cases}
\]
and $R^2_p=\operatorname{clip}(\rho_p^2,0,1)$. When $n_V=0$, the
implementation returns zero for both metrics.

This formula shows why dense membership export is unnecessary. The score needs
only per-path counts and target sums plus target-wide statistics. Therefore,
the backend can evaluate membership transiently, reduce on device, and return
one compact row per candidate with metric columns.

\section{System Design}

\subsection{Ownership Boundary}

The intended \gafime v1 architecture uses a hard ownership split. Python
exposes the public API; Rust owns validation, feature planning, scheduling,
backend selection, fallback policy, and report ownership; \cuda owns the
CUDA-specific execution boundary. The experimental ABI implements the backend
half of this contract. The current public decision-path adapter is not yet
wired to it.

\begin{itemize}
  \item An approved Rust caller passes compact, validated decision-path
  descriptors and an explicit RT policy through the GPU C ABI.
  \item \cuda validates RT representability, builds geometry, launches \optix,
  and writes compact result rows.
  \item \cuda does not discover candidate paths, mutate scheduler policy, or
  infer Python behavior. A require-RT request fails explicitly if unavailable.
  \item First-hit requests return unsupported when their finite, bounded,
  two-dimensional, non-overlap proof cannot be established.
\end{itemize}

The explicit per-call policy is
\nolinkurl{DecisionPathRtPolicy::RequireRt}, encoded as
\nolinkurl{GAFIME_DECISION_PATH_FLAG_REQUIRE_RT} in the batch. It controls
fallback only: an unavailable or unrepresentable RT request returns unsupported
instead of executing the SM comparator. By contrast, the CUDA payload reads
three process-global experimental test and profiling selectors:
\begin{itemize}
  \item \nolinkurl{GAFIME_CUDA_DECISION_PATH_RT},
  \item \nolinkurl{GAFIME_CUDA_DECISION_PATH_RT_SCORE}, and
  \item \nolinkurl{GAFIME_CUDA_DECISION_PATH_RT_GEOMETRY}.
\end{itemize}
They are not a thread-local or per-call public policy ABI. The benchmark selects
\texttt{firsthit} through the process environment and independently sets the
per-call require-RT flag so an accidental SM fallback cannot produce a timing.

\subsection{CUDA Source Split}

The implementation keeps RT code out of the generic continuous CUDA kernels:

\begin{itemize}
  \item \texttt{src/cuda/rt\_kernels.cu} contains OptiX device programs,
  RT-specific CUDA kernels, point packing, exact hit filters, and direct-score
  accumulation helpers.
  \item \texttt{src/cuda/rt\_launcher.cu} owns host-side RT planning, finite-box
  validation, OptiX pipeline setup, GAS/IAS construction, cached workspaces,
  grouped execution, and explicit comparator dispatch.
  \item \texttt{src/cuda/launcher.cu} remains the public C ABI bridge for
  decision-path RT symbols.
\end{itemize}

This source layout is part of the architectural contract. RT traversal logic is
large enough to deserve explicit ownership; hiding it inside the generic CUDA
score path would make later backend maintenance harder.

\subsection{Grouped Instanced Launch}

Candidate batches may contain many feature pairs. A single triangle GAS cannot
interpret point coordinates for all feature-pair coordinate systems at once.
The CUDA launcher groups paths by compatible feature axes, builds one triangle
GAS per group, and wraps group GAS handles in one instance acceleration
structure (IAS). Ray generation then launches
\[
  \text{launch shape} = (n,\;g,\;1),
\]
where $g$ is the number of RT groups. The instance id selects the group-local
path table, and a scatter map restores original path order before result export.
This gives \optix a large batched launch without moving candidate discovery into
the backend.

\subsection{Score Modes}

\paragraph{Bitset mode.}
\optix writes an idempotent device bitset, and a CUDA kernel reduces the bitset
with the target vector. This is the conservative parity path because it avoids
floating accumulation order in the traversal program.

\paragraph{Direct mode.}
The any-hit program updates per-path counts and target sums directly. This
removes the temporary bitset and reduction scan but uses floating atomics for
some statistics, so it is opt-in and documented with tolerance.

\paragraph{First-hit mode.}
For finite, bounded, two-dimensional groups where CUDA proves that boxes do not
overlap, the any-hit program accepts the first exact hit and terminates
traversal. This matches tree-leaf assignment: a row belongs to at most one leaf
region in a partition.

\begin{proposition}[First-hit equivalence]
Let $\mathcal{B}=\{B_1,\ldots,B_m\}$ be a group of bounded two-dimensional
decision regions such that the interiors are pairwise disjoint and the exact
open/closed predicate guard assigns every boundary point to at most one region.
For any row point $q$, first-hit traversal with the exact guard returns the same
membership vector as evaluating all path predicates and selecting the unique
inside region, if one exists.
\end{proposition}

\begin{proof}
If $q$ is outside all regions, no exact guard accepts a hit, so all membership
values are zero. If $q$ is inside one region $B_j$, disjointness and the
boundary ownership guard imply no other region can also accept $q$. Terminating
after the first accepted hit therefore records $B_j$ and cannot suppress another
valid region. The recorded membership is identical to exhaustive predicate
evaluation. \qedhere
\end{proof}

First-hit mode is fail-closed. If the finite, bounded, 2D, non-overlapping
proof is unavailable, the experimental first-hit selector returns unsupported
rather than changing semantics or silently routing that call to the SM
comparator. The independent require-RT ABI flag also forbids fallback.

RT support is also a build-time distribution choice. The default CUDA payload
is RT-disabled and has no OptiX dependency. CMake build modes \texttt{off},
\texttt{on}, and \texttt{both} produce an RT-free payload, an RT-enabled payload,
or distinct copies of each. Every measurement in this paper uses the explicitly
RT-enabled \texttt{libgafime\_cuda\_v1\_rt.so}; it is not evidence about the
standard RT-off artifact. The optional RT wheel is a separately selected GitHub
Actions artifact, not a claimed PyPI release.

\section{Numerical Policy}

The correctness policy separates Boolean membership from floating score
accumulation. Membership semantics are exact with respect to the \gafime
predicate model: \texttt{LE} means $x \le t$, \texttt{GT} means $x > t$, and
NaNs are not silently reinterpreted. The current upload records finiteness for
the entire feature matrix, not only columns referenced by a path; any non-finite
feature value makes the RT path unsupported. Non-finite target values do not
make RT unsupported, but those rows are omitted from all Pearson/$R^2$
statistics as defined above.

Path ids, result row ordering, and direct-mode hit accumulation in
\texttt{uint32\_t} remain integral under the RT row limit of
\texttt{UINT32\_MAX}. Score finalization is nevertheless single precision: the
valid-target count is accumulated as \texttt{float}, and each direct hit count
is converted to \texttt{float}. Therefore every integer count is guaranteed
exactly representable only through $2^{24}$; larger counts are not covered by an
exact-count claim. Both reported workloads use 262,144 rows and stay below this
limit. Floating Pearson and $R^2$ values may also differ because of floating
atomics or backend-specific reduction order. The present first-hit parity run
has maximum absolute score difference $1.19209 \times 10^{-7}$ against the CPU
reference, below the documented spike tolerance of $10^{-4}$.

The synthetic workloads use bounded 2D boxes over feature-pair groups. The

all-pairs-equivalent work as
\[
  W_{\mathrm{eq}} = n \times m ,
\]
where $n$ is row count and $m$ is path count. First-hit traversal does not
execute $n \times m$ explicit predicate tests. Its actual launch contains
$n \times g$ rays for $g$ compatible geometry groups, and BVH traversal prunes
the path set. Dividing $n \times g$ by the full timed score call produces an
end-to-end effective ray rate; it includes launch and programmable CUDA work and
is not an isolated RT-core counter. We report it beside $W_{\mathrm{eq}}/t$.

Each hardened score run makes six calls after one resident matrix upload. The
first timed call includes OptiX program initialization, geometry construction,
and cache population. The next five calls reuse resident state; the reported
warm number is the observed median sample, not a best-of-$N$ value. The
benchmark validates the worst parity error across the cold call and all five
warm samples, so a correct median cannot hide an incorrect outlier. Warm results
are steady-state timing evidence and must not be read as first-use latency.

\subsection{Compact Output and Score Modes}

Materializing an \texttt{f32} path-major membership matrix for
$1{,}048{,}576 \times 512$ requires 2.00 GiB. A byte mask requires 512 MiB,
the conservative device bitset requires 64 MiB, and the final two-metric result
requires only 4 KiB. Compact reduction is therefore part of the algorithm, not
an output-format detail.

The RT bitset path retains a deterministic idempotent mask. Direct mode removes
the mask scan and accumulates traversal statistics with floating atomics; it is
experimental and uses the documented $10^{-4}$ tolerance. The hash-bound timing
evidence below is limited to first-hit mode; this paper does not attach an
unarchived standalone timing claim to the other score modes.

For \texttt{optixLaunch}, the available counters report 24.932\% compute-pipe
peak, 10.878\% DRAM peak, 54.223\% achieved occupancy, 53.408\% L1 hit, and
96.864\% L2 hit, with 72 registers/thread. This supports a traversal-dominated,
cache-resident interpretation relative to packing and scatter. It does not
measure RT-core saturation directly, and the unavailable fixed-function counter
must not be inferred from SM compute or branch metrics.

\subsection{Interpretation}

The first-hit result is large because the workload matches both the BVH
algorithm and the traversal hardware:

\begin{itemize}
  \item path candidates are bounded regions, not arbitrary branch programs;
  \item the partitioned-grid invariant lets each row-group ray terminate after
  the first exact hit;
  \item grouped instancing creates a large launch rather than many tiny
  launches;
  \item score output is compact and does not copy dense membership to host;
  \item resident sessions reuse geometry, packed points, target statistics, and
  scratch buffers when inputs are unchanged.
\end{itemize}

Dense overlapping boxes do not show the same behavior. The result therefore
cannot be interpreted as a general RT-core speedup over exhaustive CUDA. The
first-hit method changes the algorithm from all-pairs testing to BVH search with
at most one accepted hit per row-group ray. A fair attribution study still
needs a CUDA baseline that exploits the same partition structure without
OptiX.

\section{Limitations}

The implementation is intentionally narrow. The fastest first-hit path currently
applies only to finite, bounded, non-overlapping 2D groups. The compact RT
decision-path score ABI supports Pearson and $R^2$ in this spike; MI and
Spearman require additional parity work. CUDA/OptiX is the only RT backend.
ROCm and Metal do not expose this RT-core path through the current \gafime ABI.

The public Python decision-path workflow does not yet invoke the compact RT
score ABI. It still materializes candidate membership before generic continuous
analysis. The paper therefore makes no end-to-end \gafime speedup claim. The
default CUDA distribution is also RT-disabled; users must select an RT-enabled
payload explicitly.

Both evaluated workloads are synthetic partition grids. The large case is
validated by a structure-aware CPU oracle rather than exhaustive all-pairs CPU
evaluation. No production ensemble paths, training loop, inference service, or
feature-mining search were benchmarked. The current SM comparator evaluates all
row-path pairs and is not an algorithmically matched partition index, so it
cannot isolate the contribution of fixed-function traversal hardware.

The evaluation uses one Ada laptop GPU. Larger desktop RTX devices or different
generations may shift the bottleneck toward acceleration-structure size,
target-stat atomic pressure, memory bandwidth, or launch scheduling. Available
Nsight Compute counters did not expose a direct RT-core saturation percentage.
First-call latency is tens to hundreds of milliseconds because it includes
program and acceleration-structure setup; resident warm timing applies only
when unchanged geometry and buffers can be reused.

\section{Future Work}

Several pieces remain before this becomes a broader GBDT acceleration method:

\begin{enumerate}
  \item wire the compact ABI through the Rust-owned public decision-path planner
  without candidate-expanded row materialization;
  \item evaluate paths extracted from real trained ensembles, not only
  synthetic partition grids;
  \item compare against a CUDA partition index with the same first-hit
  algorithmic advantage, then separate build, query, memory, and energy costs;
  \item add deterministic buffered first-hit statistics and compare them with
  direct floating atomics;
  \item extend compact RT scoring to MI and Spearman only after estimator and
  significance parity are proven;
  \item test Turing, Ampere, Ada, Hopper, and Blackwell devices and report
  acceleration-structure memory explicitly;
  \item compare against production tree-inference and GPU-GBDT systems while
  preserving the distinction between candidate scoring, inference, and
  training.
\end{enumerate}

\section{Conclusion}

This paper reports a systems mapping from bounded decision-path scoring to
hardware ray tracing traversal and on-device fused reduction. The key insight
is not that every tree operation is geometric. The useful subset is narrower:
finite low-dimensional path regions can be scored as point-in-region tests, and
tree-leaf-like non-overlap makes first-hit traversal semantically valid.

The implementation establishes a compact low-level ABI and fail-closed
representability rules, but public-path integration remains future work. On the
parity-covered RTX 4060 Laptop case, resident warm performance is $2.424$ T
membership-equivalent evaluations/s at $2.367$ G end-to-end effective rays/s
with maximum absolute score error $1.19209 \times 10^{-7}$. On the larger
oracle-validated case it is $13.621$ T membership-equivalent evaluations/s at
$0.104$ G end-to-end effective rays/s with $5.58794 \times 10^{-9}$ error. The
differing rates emphasize the central conclusion: this is a promising
combination of tree-like partition structure, BVH search, RT-assisted traversal,
and compact CUDA reduction, not evidence that RT cores accelerate arbitrary
GBDT computation.
