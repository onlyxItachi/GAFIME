# v1.1 Semantic Evidence Spine

> **Internal design and migration record.** This defines a bounded Rust-owned
> semantic vertical slice. It does not add a public Python API, change a frozen
> GPU ABI, certify device execution, establish a universal unsupervised-learning
> quality score, release RC2, or close issues #72 or #73.

## Verdict and scope

The v1.1 Core path is an internal, three-profile semantic execution path.
It represents a bounded candidate-program DAG independently from the evidence
collected about candidates and independently again from the policy that selects
them. This makes it possible to describe unsupervised, self-supervised, hybrid,
and supervised evidence honestly without overloading a supervised target slot.

The slice deliberately does not make a global claim about the eventual GPU
protocol or whether a larger semantic IR will be needed. It establishes the
smallest production-owned semantic seam that can fail closed where a backend or
evidence definition is not representable.

The Core-completion phase tests this verdict through composition, not only a
first successful example. Its bounded vocabulary is source, absolute difference,
softsign and ordered frozen centered product, with the four evidence definitions
below. It does not equate completion of this vocabulary with completion of every
future #73 learning objective. Existing supervised metric/family execution keeps
its specialized plans; those plans need not become generic DAGs.

## Separation of responsibilities

| Layer | Owns | Must not own |
| --- | --- | --- |
| Candidate program | Transform structure, canonical candidate identity, and transitive source usage | Evidence values, label interpretation, or ranking policy |
| Materialized candidate values | Values for one immutable feature frame | Reusable candidate identity or evidence decisions |
| Evidence specification | Stable measurement identity and versioned mathematical question | Particular labels, views or graph instances |
| Bound evidence / record | Actual contextual operands, provenance, support and result | Candidate identity or a universal quality score |
| Selection policy | Direction, constraints, missingness handling, and acceptance | Candidate math or implicit replacement of unavailable evidence |
| Accepted feature / discovery round | Recorded decision, explicit later-round atom eligibility and bounded reuse | Inference-time refitting or implicit promotion of rejected candidates |

An accepted candidate program may be reused with a compatible new input frame.
Its materialized values and all evidence values are input-bound and must be
recomputed; they are not transferable merely because the program identity is
the same.

## Bounded candidate-program DAG

The initial program vocabulary is deliberately small:

- `AbsDiff`
- `Softsign`
- ordered, frozen centered product

The centered-product program records operand order and its centering semantics
when the program is created. Evaluation must not reinterpret either from an
anchor, paired view, target, or later feature ordering.

The three independent structural bounds must not be conflated:

- Logical arity counts distinct immediate operands (a source has arity one).
- Depth counts the longest derived path from a source.
- Source arity counts distinct source-feature leaves reachable through that
  DAG.
- Bounds, cycles, malformed definitions, and foreign identities fail closed at
  construction or validation boundaries.

The candidate layer owns the exact canonical-ID representation. Evidence and
policy refer to that identity; neither re-derives candidate math or creates a
second identifier scheme.

IDs are opaque, process-local registry-token/slot pairs, not serialized hashes.
Cloning a program does not create another identity authority. Frozen means are
explicit caller-declared arithmetic parameters, not automatically fitted state;
their exact profile-native f32/f64 bits and operand order participate in canonicalization. This
slice does not certify how a caller estimated those constants. Future learned
parameters need explicit fitting provenance before a fitting API is promised.

## Evidence definitions, values, and context

Evidence has a stable, named, versioned definition plus a contextual value. A
value is bound to an immutable feature frame and its exact row alignment,
including provenance sufficient to distinguish same-length but differently
ordered inputs. Missing evidence is explicit state, not a numeric zero or a
silently substituted measurement.

The first definitions are:

| Definition | Meaning | Availability boundary |
| --- | --- | --- |
| `absolute-pearson/reference/v1` | Absolute Pearson association between a candidate and a registered reference | Requires nonconstant aligned operands; a reference is not a label |
| `signed-pearson/aligned-view/v1` | Signed Pearson association for the same program across aligned views | Requires the declared paired view and exact row alignment |
| `uncentered-edge-energy-ratio/v1` | Uncentered graph edge-energy ratio for candidate values | Requires a valid graph and nonconstant candidate; undefined reduction is unavailable |
| `absolute-pearson/labeled-subset/v1` | Absolute Pearson association with actual labels on an explicit subset | Requires at least two actual labels and nonconstant operands |

For graph evidence, “uncentered” means that no mean-centering is inserted
before the edge-energy calculation. The exact ratio is
`sum(w * (z_i - z_j)^2) / sum(w * (z_i^2 + z_j^2))` in declared edge order.
Edges form an undirected multiset; duplicates contribute repeatedly. Self-loops,
nonpositive/nonfinite weights and invalid endpoints fail closed. This ratio is
translation-sensitive and is **not** a centered Laplacian score. Those details
belong to the versioned evidence definition, not to a candidate ID.

Frame schema, row domain, ordered row keys and evaluation role must agree for
paired views. Graphs and labeled subsets bind to an exact immutable frame ID.
Provenance, row-domain and split declarations remain trusted caller assertions:
this layer does not prove holdout disjointness, absence of leakage, graph quality
or a valid statistical experiment. Roles record context, not authorization.

Optional labels remain distinct from anchors and paired views. A label-free
request produces unavailable label evidence rather than a fabricated target.
Similarly, a numerical value, an undefined/invalid statistic, and unavailable
evidence must remain distinguishable for policy handling.

There is no implicit aggregate across these definitions and no universal
quality score in this slice. A later policy may use one or several evidence
channels, with an explicit direction and missingness rule; the evidence record
alone does not prove a general unsupervised-learning result.

`EvidenceSpec` is a transferable process-local measurement identity, not session
authority or a serialized schema. A policy can keep that identity while
`rebind` supplies new labels, graph or paired view of the **same measurement
kind**. Old tables and acceptance records retain their immutable old bindings.
Changing the mathematical definition requires a new specification. New context
does not change the candidate program. Duplicate immutable operand bindings in
one evaluation share native work but retain separate channel records.

Selection uses one primary channel with maximize/minimize direction, inclusive
constraints in each channel's own units, then deterministic FeatureId ties.
This is deliberately not a weighted sum or an implicit cross-paradigm utility.
Missing primary evidence rejects or errors. A constraint may explicitly ignore
unavailable optional evidence; absence never silently becomes a numeric value.
All required error-mode channels are inspected even if another constraint has
already rejected a candidate. fp32 thresholds are quantized to f32; its report
container only exactly widens the resulting f32 values, not their arithmetic or
selection resolution.

## Core execution and backend boundary

The executor supports Core fp32, mixed and fp64. Core evaluates the bounded program and
the evidence it can represent; unsupported requests are reported explicitly.
New GPU evidence execution is intentionally unsupported in this phase.

Existing CUDA, ROCm, and Metal continuous descriptors remain legitimate
lowerings for their existing supervised continuous work. They do not acquire
new semantic meanings through this document: a target remains actual target
data, and it is not repurposed as an anchor, a paired view, a graph input, or a
label substitute. Consequently, this vertical slice needs no new native GPU
ABI addition.

That is a bounded capability decision, not evidence that a future GPU semantic
IR is unnecessary. Device support for paired views or graph evidence will need
an explicit representation of the relevant operands or graph context and a
separate compatibility decision.

## Production migration boundary

The supervised extraction is a real production-library migration, not a
test-only facade. It moves canonical supervised unary-strength aggregation and
shortlist ordering into the Rust semantic layer while preserving the existing
binding surface.

| Existing area | v1.1 disposition | Compatibility boundary |
| --- | --- | --- |
| `gafime-py` continuous `PrecisionUnaryStrengths` policy | Canonical implementation is extracted to `semantic::supervised::SupervisedStrengths`; the binding retains a compatibility alias and shape conversion | f32/f64 lanes, NaN behavior, `.max` behavior, order/ties, metric compatibility, and seeded policy behavior remain migration invariants |
| `unary_strengths_from_table` binding path | Delegates after boundary validation instead of maintaining a second policy implementation | No public Python API change |
| `plan::combos::legacy_higher_feature_order*` | Removed; `semantic::supervised` owns shortlist ranking and seeded shuffle, including CPU significance callers | CPython-compatible discarded unary shuffle, stable unordered ties and backend producer order are preserved |
| Existing continuous planners and GPU descriptors | Retained as existing supervised execution/lowering machinery | No new evidence semantics are inferred from old descriptors |
| PR92 experiment bridge/catalog | Does not ship as this production semantic path | No catalog-mediated fake-target protocol |
| Other legacy planners | Explicitly deferred for later migration | No broad planner rewrite or deletion in this slice |
| Frozen Python and native ABI surfaces | Unchanged | The new semantic API is internal Rust only |

The shared comparator is intentionally smaller than either policy. Supervised
compatibility retains its historical NaN/tie order and RNG consumption; new
evidence selection rejects unavailable primary values and uses deterministic
identity ties. Significance's distinct nonfinite reduction remains explicit.
No generic EvidenceTable adapter is inserted around every old target-based
kernel, and no claim is made that every old family already uses semantic IDs.

## Executable slice and validation obligations

Run the internal native cookbook (no Python API or GPU payload required):

```bash
cargo run -p gafime-cpu --example semantic_evidence
cargo test -p gafime-orchestrator semantic::
cargo test -p gafime-cpu --test semantic_spine
cargo test -p gafime-cpu --test semantic_rounds --test semantic_policy --test semantic_native_reuse
```

The [cookbook](../crates/gafime-cpu/examples/semantic_evidence.rs) declares
abs-difference/softsign programs, evaluates four channels with labels absent,
selects by paired consistency, constructs and selects a child from the accepted
program, then materializes that child on new unlabeled rows. That demonstrates
target-free execution, **not** general feature utility or a learned representation.

For a bounded internal execution diagnostic, run
`cargo run --release -p gafime-cpu --example semantic_core_sanity` on an idle
host. It asserts cold/resident evidence equality before reporting per-evaluation
samples and observed node/cache counts for 8,192 rows and 78 candidates, with
one, four and the normal default number of Rayon workers. Paired-view programs
are intentionally recomputed: the bounded cache retains one primary frame, not
every supplied view. This measures internal semantic evaluation, excluding
declaration and acceptance; it is neither public product throughput nor a
cross-backend comparison. Record the exact commit, binary hash and environment
alongside any retained samples.

The installed-wheel
[supervised snapshot](../tests/release_measure/semantic_01_supervised_snapshot.py)
emits ordered candidate, metric, permutation and bootstrap bits for all three
profiles, all four existing supervised metrics and two seeds. Run it outside
the source checkout with each intended wheel, then compare its JSON bytes.
One/default worker comparisons use separate processes so Rayon initializes
under the requested worker policy. This supplements, not replaces, the public
NumPy, family-generation and installed Python contract suite.

The [integration tests](../crates/gafime-cpu/tests/semantic_spine.rs),
[multi-round tests](../crates/gafime-cpu/tests/semantic_rounds.rs),
[policy/precision tests](../crates/gafime-cpu/tests/semantic_policy.rs), registry
tests and supervised-policy tests cover these obligations. Exact-head run/review
results belong in the draft PR; this document is not a substitute for CI.

- Program construction rejects cycles, out-of-bound transitive arity/depth,
  malformed nodes, and foreign identities.
- `AbsDiff`, `Softsign`, and ordered frozen centered-product evaluation agree
  with small reference cases without changing their canonical identities.
- Logical arity/depth and distinct-source arity are tested separately on
  nested programs.
- A feature-frame or row-alignment mismatch is rejected even when row counts
  happen to match.
- Evidence records retain definition/version, frame/subset identities and
  declared provenance. Compatibility checks enforce schema/domain/ordered keys/
  role and exact graph/label frame binding, not equality of descriptive
  provenance; missingness is never coerced to zero.
- Anchor, paired-view, graph, and optional-label evidence remain separate
  channels; absent labels cannot become anchor-derived pseudo-labels.
- Graph reductions mark undefined denominators unavailable and preserve their declared edge
  convention in provenance.
- Supervised migration regression cases compare f32/f64 lanes, NaNs, empty
  rows, unknown metrics, tie bits, order, and seeded behavior against the
  retained compatibility path.
- An explicit request for unsupported new GPU evidence fails closed, while
  existing supervised descriptor behavior remains outside this new executor.
- Public Python and frozen-ABI surface checks demonstrate that this internal
  migration did not expand those contracts.

### Lifecycle correction from adversarial testing

The initial slice retained only the latest accepted batch. A counterexample
accepted two independent atoms and then composed them: the old implementation
executed four nodes rather than only the new composite. Acceptance now admits a
bounded union of materializations for one exact frame. Failed or empty selection
does not evict previous atoms. Exceeding the retention ceiling fails atomically;
the caller can explicitly clear values without revoking accepted programs.

`begin_round(&accepted)` replaces unrestricted session registry mutation. A round
can use raw sources, the explicitly supplied same-owner accepted atoms, and
programs explicitly declared in that round (canonical redeclaration may reuse
an identical existing program). Merely knowing a rejected/old program's identity
does not grant later-round operand eligibility. Evaluation requires an active
round; evidence from an earlier round cannot be accepted in a later one.
Programs remain immutable, and new-row inference uses accepted programs without
labels or reapplying discovery policy. Same-frame accepted inference outputs
also join the bounded retained bank; retention failure never silently evicts
other accepted outputs. Closing the session fails all later work
closed. Registry node/depth/arity and round ceilings bound repeated discovery;
this is not an unbounded search/garbage-collection system.

### Resource and trust limits

Registry defaults are 65,536 nodes, logical/source arity eight and depth eight;
hard maxima are 65,536 nodes, arity 64 and depth 64. Sources and derived nodes
share the node budget. This first vocabulary rejects repeated immediate operands;
overlapping transitive sources remain valid. Input frames are finite profile-native f32/f64 with
at most one million rows and a 256 MiB matrix-plus-row-key budget. There are at
most 32 channels and 65,536 candidate/channel cells per evaluation.

`SessionLimits` explicitly bounds numeric execution bytes (at most 512 MiB),
retained bytes (at most half of that budget), discovery rounds (default 64,
maximum 1024) and structural candidate row/edge work units (default 128 million,
maximum one billion units). This is admission control, not actual kernel visits, a FLOP count or a
wall-clock guarantee. Checked dependency/channel accounting rejects oversized
work before native dispatch. Accepted-cache bytes are reserved before primary
and sequential paired-view work; label-gather scratch is bounded before use.
These are not total process RSS limits: caller-owned frames, metadata and
retained evidence tables are separate. Changing the exact frame drops the old
cache before allocating new execution banks. Evidence is never cached across
evaluations. Candidate overflow fails the evaluation before a statistic can
silently filter rows.

Source columns and retained values share immutable `Arc<Vec<T>>` storage;
materialization does not copy source payloads or copy completed vectors into a
second Arc allocation. Native candidate-level Rayon execution preserves ordered
per-candidate arithmetic and deterministic result placement. The Core precision
routes remain:

| Profile | Storage / pointwise | Reductions / ranking |
| --- | --- | --- |
| fp32 | f32 | f32 |
| mixed | f32 | f64 |
| fp64 | f64 | f64 |

Pearson uses the existing production SIMD statistics primitives. The small graph
primitive is ordered in declared edge order and follows the same reduction
domains; it does not claim SIMD or an unsupported hardware speedup. One/four
worker multi-round tests compare evidence, selection and inference bits.

Reference tests use exact f32 values where representable and `1e-10` for simple
analytic f64 ratios/correlations; that is an internal test tolerance, not a new
cross-backend/public numerical contract. Existing supervised bit-parity gates
remain unchanged. No payload, distribution, dependency or version changed.

## Deliberate non-goals

This record does not claim GPU acceleration for new evidence, a complete
replacement of every legacy planner, a performance comparison, a benchmark
result, a general theory of unsupervised learning, RC2 readiness, or completion
of #72 or #73. It instead preserves a narrow, inspectable migration path:
candidate semantics first, explicitly contextual evidence second, policy third,
and future backend lowerings only where their inputs and failure behavior can be
represented faithfully.
