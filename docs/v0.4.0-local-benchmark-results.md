Local run date: 2026-05-17

was used.

- XGBoost 3.2.0

## Readout

- The discrete family clearly closes the continuous-only gap on the synthetic
  threshold and rectangle tasks.
- Pearson and `r2` produce identical rankings where `r2` is Pearson squared in
  the current metric implementation.
- Mutual information is useful on threshold-like data and did well on
  California Housing and both synthetic threshold tasks.
- Spearman is materially slower in this runner and did not dominate the other
  metrics in this pass.
- Friedman1 is not a threshold/rectangle problem; tree baselines remain much
  stronger there, which is expected and useful as a guard against overstating
  the new feature family.
- Small/classification datasets such as Wine and Breast Cancer are near ceiling
  already, so improvements are not very informative.

## Focused California Heavy Run

Follow-up command:

```bash
.venv/bin/python tests/benchmark_california_heavy.py
```

This run used the full California Housing dataset, `backend="auto"` resolving
to `cuda-native`, dense quantiles, all 8 features for discrete planning,
all 28 feature pairs for rectangles, and a larger candidate budget.

Observed:

- Train samples: `15480`
- Test samples: `5160`
- Continuous pair features: `28`
- Discrete candidates scored: `303548`
- Total reported interactions: `303584`
- Engine candidate scoring time: `4.8269s`

Scores:

| Model | Test R2 |
|---|---:|
| Raw RidgeCV | 0.591099 |
| Continuous GAFIME + RidgeCV | 0.614583 |
| Continuous + top 500 discrete + RidgeCV | 0.638824 |
| Continuous + top 1000 discrete + RidgeCV | 0.643144 |
| Continuous + top 2000 discrete + RidgeCV | 0.648160 |
| Continuous + diverse 500 discrete + RidgeCV | 0.637908 |
| Continuous + diverse 1000 discrete + RidgeCV | 0.642494 |
| Continuous + diverse 2000 discrete + RidgeCV | 0.664880 |
| Raw HistGradientBoostingRegressor | 0.846251 |

Interpretation:

- The compute budget was not the primary blocker in this run; GAFIME scored
  over 300k discrete candidates in under 5 seconds.
- Increasing selected generated features from 500 to 2000 improved RidgeCV,
  especially with diversity-capped selection, but it did not close the gap to
  recursive tree models on California Housing.
- Top global Pearson-ranked candidates are dominated by `MedInc` gates. This
  suggests California needs residual/conditional discovery, especially for
  geography effects, rather than only more one-shot global candidate scoring.

## Focused California Split-Aware Ranking Run

The heavy California script was updated to stop ranking discrete candidates by
Pearson-only report metrics. It now scores a stratified candidate pool with:

- mutual information,
- soft variance/impurity reduction,
- residual absolute correlation,
- residual R2 gain after the continuous GAFIME baseline,
- held-out RidgeCV gains for selected feature sets,
- shuffled 3-fold RidgeCV diagnostics for selected feature sets.

Command:

```bash
.venv/bin/python tests/benchmark_california_heavy.py
```

Observed:

- Backend: `cuda-native`
- Discrete candidates reported by engine: `303548`
- Non-Pearson selection pool: `9212`
- Engine candidate scoring time: `4.1282s`

After adding native CUDA selection-score support, the same benchmark reported:

- Selection backend: `cuda-native`
- Selection-score time over the `9212` candidate pool: `0.0515s`

Held-out test R2:

| Model | Test R2 |
|---|---:|
| Raw RidgeCV | 0.591099 |
| Continuous GAFIME + RidgeCV | 0.614583 |
| Continuous + balanced top 500 discrete + RidgeCV | 0.751686 |
| Continuous + balanced diverse 500 discrete + RidgeCV | 0.765140 |
| Continuous + balanced diverse 2000 discrete + RidgeCV | 0.781393 |
| Continuous + residual-heavy diverse 500 discrete + RidgeCV | 0.762057 |
| Continuous + residual-heavy diverse 2000 discrete + RidgeCV | 0.790026 |
| Raw HistGradientBoostingRegressor | 0.846251 |

This confirms that Pearson-only discrete ranking was the wrong selector for
California-style split candidates. The split-aware/residual-aware ranking moved
the best RidgeCV result from `0.664880` to about `0.790` without changing the
candidate family. The CUDA selector now computes the split-aware scores on GPU;
the remaining benchmark time is dominated by downstream RidgeCV fitting over
large generated feature matrices.

The gap to tree models is now smaller but still real. The remaining likely
issue is not candidate budget; it is that tree models perform staged residual
splitting recursively, while the current engine still does a single generation
pass followed by a flat linear model.

Release-prep note: `EngineConfig.discrete_ranking` now defaults to
`"split_aware"`, so the engine report itself orders discrete candidates with
the same non-Pearson selector family while preserving `metric_names` for
reported metrics.
