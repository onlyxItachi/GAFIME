# GAFIME v0.4.6 Metal Native Backend Notes

This document tracks the local Metal backend implementation work before release
approval. It is intentionally focused on architecture and validation.

## Scope

- Native Apple Silicon Metal backend through `NativeMetalBackend`.
- Shared-memory Metal matrix ABI for continuous interaction batches.
- Continuous interaction arity support from 1 through 5.
- Soft discrete feature scoring on Metal.
- Time-series feature scoring on Metal for lag, delta, velocity,
  acceleration, rolling mean, rolling standard deviation, and rolling sum.
- Adaptive soft-discrete selector metrics on Metal:
  - `mutual_info`
  - `variance_reduction`
  - `residual_abs_corr`
  - `residual_r2_gain`
- JSON-serializable `DiagnosticReport.to_dict()` output.
- GitHub Apple Silicon workflow for wheel and Metal smoke
  validation.

## Backend Behavior

Metal now uses package-local `gafime_metal.dylib` plus
`gafime_kernels.metallib` when available. The Python wrapper sets the metallib
path before probing the device so installed wheels can load shaders without
depending on the process working directory.

The main continuous path uses a global matrix buffer with
`MTLResourceStorageModeShared`, which matches Apple Silicon unified memory. The
host still copies Python/native buffers into shared `MTLBuffer` storage, but it
does not perform PCIe-style host/device transfers.

Hard discrete mode remains unsupported on GPU backends and must raise:

```text
GPU feature engineering with discrete hard mode is not supported!
```

## Current Limitations

- Metal report metrics are computed natively for `pearson` and `r2`.
  `spearman` and `mutual_info` report completion currently routes through the
  C++ Core backend.
- Final Metal shader compilation and runtime behavior must be validated on the
  GitHub Apple Silicon workflow because local development does not have an
  Apple Silicon Metal device. The workflow defaults to `macos-26` and can use
  `macos-26-xlarge` when that larger runner is enabled for the repository.

## Validation

Manual workflow:

```bash
gh workflow run metal_macos26_lab.yml
```

To force the larger runner after it is enabled:

```bash
gh workflow run metal_macos26_lab.yml -f runner_label=macos-26-xlarge
```

Expected artifacts:

- `runner-specs.txt`
- `metal-device.txt`
- `wheel-contents.txt`
- `installed-wheel-metal-smoke.json`
- one macOS arm64 lab wheel

Linux-side checks before dispatching the Metal lab:

```bash
python -m py_compile gafime/backends/native_metal_backend.py gafime/reporting/report.py gafime/cli.py
python tests/test_v045_native_spine.py
python -m gafime.cli --check
```
