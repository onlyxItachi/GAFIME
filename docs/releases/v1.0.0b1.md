# GAFIME v1.0.0b1 Aborted Packaging Checkpoint

`v1.0.0b1` was tagged as a packaging-only checkpoint but did not complete as a
GAFIME release. CUDA and ROCm payload files reached PyPI, the attempted
separate Metal publication failed, and the fail-closed workflow correctly
withheld the Core package and GitHub Release. Consequently
`gafime==1.0.0b1` is unavailable and the published payloads cannot resolve
their exact Core dependency.

It did not change metric mathematics, kernel implementations, planner
behavior, or numerical tolerances.

## Attempted Distribution

The checkpoint attempted to expand the standard bundle from 11 to 13 artifacts
by moving Metal out of the macOS Core wheel. That architecture was not adopted.
The standing contract retains 11 standard artifacts and embeds Metal only in
the Apple Silicon Core wheel.

Every wheel uses the CPython 3.10 Stable ABI. Cibuildwheel builds one
`cp310-abi3` artifact per platform and tests that same artifact on CPython 3.10,
3.11, 3.12, 3.13, and 3.14. The filename does not mean support is limited to
Python 3.10.

## Metal

The attempted `gafime-metal` distribution was not published and is not part of
the standing package architecture. Apple Silicon uses the paired
`libgafime_metal_v1.dylib` and `gafime_metal_v1.metallib` embedded directly in
the selected `gafime` macOS arm64 Core wheel.

The Metal parity gate uses the approved absolute fp32 release tolerance
`GAFIME_METAL_PARITY_TOLERANCE=0.00005`. Apple-hardware run `30207767348`
measured a worst-case absolute delta of `4.045665264e-6` across the finite and
NaN/Inf parity datasets, so the release bound is about `12.36x` the observed
maximum and `40x` tighter than the former provisional guard. The complete
per-metric record and its limitations are in
[the Metal parity evidence](../evidence/metal-parity-macos26.md).

## ROCm

The standard `gafime-rocm` payload uses the explicit immutable `system` policy:

- built from pinned ROCm 7.2.3 inputs for the established 13 GFX targets;
- no bundled HIP/HSA/ROCm userspace;
- no wheel-private ROCm directory, repair SBOM, RPATH, or RUNPATH;
- one declared external runtime prerequisite, `libamdhip64.so.7`, from one
  coherent system ROCm 7.2.x installation.

The thin wheel retains its truthful `linux_x86_64` tag. PyPI rejects raw Linux
wheels, and the external ROCm prerequisite prevents a truthful manylinux tag.
The wheel is therefore attached to the GitHub Release while PyPI publishes the
matching source distribution. The separately identified
`gafime-rocm-bundled` policy is not part of this release.

## Publication Safety

The failed Metal lane prevented Core and GitHub Release publication exactly as
designed. The checkpoint is not repaired in place because PyPI filenames are
immutable and the attempted Metal split is not the desired contract.

`v1.0.0b0` remains immutable. Its files are not deleted or replaced.

## Evidence Boundaries

- ABI3 interpreter testing establishes Python 3.10-3.14 compatibility for each
  built platform wheel; it does not create five distinct wheel files.
- The ROCm clean-install smoke uses pinned ROCm 7.2.3 userspace without a
  physical GPU. Numerical ROCm runtime evidence remains bounded to separately
  recorded physical-device gates.
- Metal execution evidence comes from hosted Apple hardware.
- No performance improvement is claimed for this packaging-only hotfix.

## Deliberate Non-Claims

The [v1.0.0b0 numerical non-claims](v1.0.0b0.md#deliberate-non-claims) continue
to apply unchanged. In particular, scale-normalized covariance cannot recover
an interaction product that overflowed before normalization.

Release validation and recovery procedures are in
[release-operations.md](release-operations.md).
