# GAFIME v0.4.5 Release Notes

v0.4.5 is a native-spine cleanup and performance-architecture release. It
removes legacy fallback paths, makes the C++ Core backend the CPU execution
spine, and upgrades CUDA orchestration so broad continuous scans use arity-aware
native batches instead of the old pair-specialized APIs.

## Public API Changes

- `backend="numpy"` is no longer a production backend option.
- `backend="cpu"` now resolves to the C++ Core backend.
- `backend="auto"` resolves only native backends. If no native backend can load,
  the engine fails clearly instead of silently running a pure Python/NumPy
  fallback scorer.
- `from gafime import subfunctions` is the user-facing alias for Rust helper
  APIs. Direct `import gafime_cpu` is treated as an implementation detail.
- `EngineConfig` now includes explicit time-series candidate controls:
  `enable_time_series_functions`, `time_series_lags`, and
  `time_series_windows`.
- `ComputeBudget` now includes `max_time_series_candidates` and
  `top_k_features_for_time_series`.
- CUDA report metrics currently support `("pearson", "r2")`. Explicit CUDA
  requests with unsupported report metrics raise a clear error; `backend="auto"`
  falls through to C++ Core for metrics that require the full CPU reporter.

## Engine and Backend Changes

- Removed the NumPy backend path. `backend="auto"` resolves only native
  backends; `backend="cpu"` resolves to the C++ Core backend.
- Removed the old standalone CPU shared backend from the build. CPU execution is
  owned by `gafime_core`.
- C++ Core scoring exposes one production memory contract:
  `score_combos_buffer(NativeMatrixBuffer, NativeVectorBuffer, ...)`.
  Old sequence/flat scorer bindings are removed from the Python extension
  surface.
- CUDA no longer exports the old per-call fused interaction, legacy feature
  interaction, pair-only interleaved, or contiguous bucket APIs.
- CUDA broad continuous scoring uses `gafime_cuda_matrix_compute_batch`: one
  full column-major feature matrix upload, global feature-index descriptors, and
  homogeneous arity template launches.
- CUDA bucket batch scoring remains for compact explicit candidate families such
  as time-series transforms.
- The CUDA batch spine supports arity 1, 2, 3, 4, and 5.
- CUDA report metrics fail fast unless the requested report metrics are
  supported by the batch path: `pearson` and `r2`.
- Native data movement now uses fp32-owned C++ buffers by default, preserving
  the GPU-oriented precision/performance policy used by previous NumPy
  coercion paths.

## Batch ABI

```text
kinds        [N]
indices      [N * arity]
ops          [N * arity]
interactions [N * max(arity - 1, 1)]
ts_params    [N * 4]
stats        [N * 12]
```

Rust `subfunctions.BatchScheduler` groups candidates by homogeneous arity first,
then applies cache-local feature ordering before CUDA launch.

## Discrete and Time-Series Families

- Discrete GPU execution remains soft/vectorized only. Hard discrete mode on GPU
  raises `GPU feature engineering with discrete hard mode is not supported!`.
- Discrete report scoring and split-aware selection are wired to CUDA selector
  kernels when CUDA is selected and supported report metrics are requested.
- Time-series feature engineering is now an explicit Engine candidate family,
  not a hidden `apply_op_fast` rolling operation.
- Time-series candidate kinds: lag, delta, velocity, acceleration, rolling mean,
  rolling standard deviation, and rolling sum.

## CUDA Selector Profiling Notes

The adaptive discrete selector uses soft-binary masks and a target histogram
with `hist_in[target_bins]` and `hist_out[target_bins]`. For the largest v0.4.x
template this is `2 x 96` histogram storage, so the histogram size itself is not
the occupancy problem. The larger shared-memory allocation is the reducer
scratch area, `partials[10 * BLOCK_SIZE]`.

NCU showed that the original `<96>` selector was register-limited because the
final target-bin MI loops were force-unrolled. The loops now use
`#pragma unroll 1`, which keeps the template shape static without exploding
register pressure.

Representative local result on the RTX 4060 Laptop GPU profile:

```text
gafime_discrete_selection_adaptive_kernel<96>
before: 215 registers/thread, ~15% achieved occupancy, ~8.95 ms
after:   56 registers/thread, ~59% achieved occupancy, ~2.70 ms
```

No register spilling was observed in either profile. Mixed candidate-kind
branching is secondary; target bins are precomputed on the host and are not
recomputed inside the kernel. The remaining selector hotspot is shared-memory
atomic contention when target bins are extremely skewed or low-cardinality.

This is a known performance note, not a correctness issue. The skewed-bin
atomic path remains a future native-kernel optimization target.

## Benchmark Summary

The release benchmark is committed as
`tests/benchmark_v045_native_spine.py`. Full local results are documented in
`docs/v0.4.5-native-spine-benchmark-results.md`.

Same source-built benchmark, v0.4.1 vs v0.4.5:

| Workload | Backend | v0.4.1 | v0.4.5 | Result |
|---|---:|---:|---:|---|
| 8,192 rows, 12 features, 1,585 interactions | CPU/Core | 0.0289 s | 0.0098 s | ~2.9x faster |
| 8,192 rows, 12 features, 1,585 interactions | CUDA | 0.2644 s | 0.1762 s | ~1.5x faster |
| 32,768 rows, 24 features, 55,454 interactions | CPU/Core | 0.5069 s | 0.5082 s | effectively unchanged |
| 32,768 rows, 24 features, 55,454 interactions | CUDA | 11.8308 s | 0.6363 s | ~18.6x faster |
| 131,072 rows, 24 features, 55,454 interactions | CPU/Core | 7.4427 s | 3.0983 s | ~2.4x faster |
| 131,072 rows, 24 features, 55,454 interactions | CUDA | MemoryError, 27.1 GiB allocation | 0.8484 s | workload now completes |

The main CUDA difference is structural: v0.4.5 does not materialize the large
candidate matrix that caused the v0.4.1 large CUDA run to request 27.1 GiB.
Instead, it keeps the input matrix resident and streams homogeneous arity
batches through native descriptors.

## Local Verification

Commands used in the local working tree:

```bash
uv pip install -e .
python -m compileall -q gafime
python -m unittest discover -s tests -p 'test_*.py'
PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1 cargo test --manifest-path src/cpu/gafime_cpu/Cargo.toml
nm -D gafime/libgafime_cuda.so | c++filt | rg 'gafime_cuda_matrix_compute_batch|gafime_bucket_compute_batch|gafime_discrete'
```

The CUDA symbol check should show:

```text
gafime_bucket_compute_batch
gafime_cuda_matrix_compute_batch
gafime_discrete_soft_batch_cuda
gafime_discrete_selection_adaptive_cuda
```

and should not show legacy feature-interaction, contiguous-bucket, or per-call
fused-interaction symbols.
