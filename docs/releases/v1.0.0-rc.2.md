# GAFIME v1.0.0-rc.2 — Validation And Artifact Identity Hardening

Draft candidate note. This document describes the current local RC2 hardening
proposal; it is not a publication record or release approval. Follow
[STATUS.md](STATUS.md) and the canonical GitHub Releases for live train state.

Planned repository/Cargo identity: `1.0.0-rc.2`; canonical tag and GitHub Release:
`v1.0.0-rc.2`; Python/PyPI identity: `1.0.0rc2`. The source retains its RC1
identity until the reviewed RC2 preparation change lands.

## Proposed Changes

- The advanced compatibility `BatchScheduler` rejects zero capacity with a
  clear `ValueError`, and large positive capacities cannot overflow its size
  hints.
- Shared typed-buffer ABI validation inspects the version/size header before
  reading an accepted prefix. Complete ABI 1.1 prefixes and compatible additive
  tails remain supported without changing the ABI layout.
- Generated pipeline guidance encodes dataset paths and target-column names
  as Python data literals.
- Benchmark wheel/runtime identity checks verify claimed member hashes against
  archive bytes and reject ambiguous installation destinations. Synthetic
  comparison fixtures use deterministic ZIP metadata.
- Manual Core benchmark dispatch validates the live repository-owned PR source
  before checkout, with the existing later checks retained.
- Resident NumPy analysis stages private immutable input bytes so content
  fingerprints, native ingest, and target replacement cannot diverge after a
  caller-side write. Acquisition is not an atomic transaction with an external
  writer; the lifecycle guide documents that limit and the cache-hit copy cost.
- Host C++ ABI validation fixtures use C++23; external C integration fixtures
  remain C11. CUDA payloads retain the documented C++20 compiler requirement.

The supported public API, numerical profiles, execution ownership, and package
topology remain those established by [RC1](v1.0.0-rc.1.md). No new feature family,
precision package, standalone Metal package, or RT/OptiX distribution is added.

## Qualification And Claim Boundaries

Local regression tests and independent patch reviews support this proposal.
They do not establish final RC2 hosted checks, a frozen artifact bundle,
physical backend qualification, or publication readiness. Those gates must bind
to the reviewed, settled RC2 source under the
[release operations runbook](release-operations.md).

The completed deep security review is evidence for its original source
checkpoint. Finding disposition and regression evidence accompany the
hardening work; they do not certify a later candidate as vulnerability-free.
No universal throughput or comparative GPU performance claim is made.
