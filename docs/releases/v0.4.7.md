# GAFIME v0.4.7 Release Notes

v0.4.7 is the ROCm/HIP development and GPU payload policy release.

It adds the first native ROCm backend path while explicitly documenting why CUDA
and ROCm binary payloads must be split for distribution. Python package
installers can select wheels by OS and CPU architecture, but they cannot choose
a different x86_64 wheel based on whether the local GPU is AMD, NVIDIA, or both.

## Highlights

- Added native HIP kernel source at `src/rocm/kernels.hip`.
- Added `NativeRocmBackend` with explicit `backend="rocm"` and `backend="hip"`
  resolution.
- Added ROCm payload build controls:
  - `GAFIME_ROCM_ARCHS=<gfx-target>[,<gfx-target>...]`
  - missing `hipcc` fails the `gafime-rocm` payload build
- Added local ROCm validation on an AMD iGPU path.
- Documented the vendor GPU payload package policy:
  - `gafime` remains the stable Python/Core package.
  - `gafime-cuda` carries CUDA native binaries.
  - `gafime-rocm` carries ROCm/HIP native binaries.
  - `gafime[cuda]` and `gafime[rocm]` are the intended convenience install
    selectors when payload packages are published.
- Documented mixed AMD iGPU + NVIDIA dGPU safety:
  - `backend="auto"` defaults to CUDA when both payloads are installed.
  - ROCm is initialized only through explicit `backend="rocm"` /
    `backend="hip"`.
  - GAFIME should not initialize CUDA and ROCm just to discover devices.
- Refreshed Docker files so they use the real source build pipeline instead of
  manually compiling obsolete native paths.

## Distribution Artifacts

- `gafime`: base wheels for Python API, C++ Core, Rust subfunctions, backend
  resolver, and Metal on macOS arm64. These wheels must not contain CUDA or
  ROCm payload packages.
- `gafime-cuda`: CUDA payload wheels for Linux/Windows x86_64 plus a source
  distribution. This package carries `gafime_cuda` and the CUDA shared library.
- `gafime-rocm`: ROCm/HIP payload source distribution for Linux/Windows x86_64
  HIP toolchains. This package carries `gafime_rocm` and builds the HIP shared
  library with local `hipcc`.

## Backend Policy

Current v0.4.7 policy:

| Platform / installed payloads | `backend="auto"` priority |
|---|---|
| macOS arm64 | `metal -> core` |
| Linux/Windows x86_64 + CUDA payloads | `cuda -> core` |
| Linux/Windows x86_64 + ROCm payloads | `rocm -> core` |
| Linux/Windows ARM64 | `core` |

ROCm remains explicit while the split payload packaging work is finalized.

## Validation

Local ROCm development validation:

```text
hipGetDeviceCount -> rc=0, n=1
gafime --check -> ROCm/HIP available (rocm-native, AMD Radeon Graphics gfx/hip 11.5)
python -m pytest tests/test_v045_native_spine.py tests/test_rocm_native_backend.py -q
16 passed
```

Skill and diagnostic updates:

- `check-install` reports installed vendor payload packages.
- `platform-detect` recommends `gafime[cuda]` or `gafime[rocm]` based on
  visible hardware hints without importing both GPU runtimes.
- `troubleshoot-backend` documents CUDA, ROCm, Metal, and Core failure modes.

## Docker

Docker files are now source-build development containers:

- `Dockerfile`: CUDA source-build development image using CUDA 13.2, compiler
  tooling, Rust, CMake, and GAFIME development/benchmark dependencies.
- `Dockerfile.smoketest`: CPU/Core smoke image.
- `docker-compose.yml`: separate CUDA dev and Core smoke services.

These containers are not distribution images. GAFIME distribution remains
PyPI/wheel based. The Docker images are for source builds, backend development,
profiling, and maintainer validation. Additional workstation packages can be
layered with the `EXTRA_PIP_PACKAGES` Docker build argument.

## Notes

The ROCm payload split is the distribution direction. The release keeps package
selection explicit to avoid unsafe mixed-runtime probing on machines with both
AMD and NVIDIA GPUs.
