# GAFIME v0.4.0 Release Notes

GAFIME v0.4.0 is the discrete function engine release. It keeps the existing
engine API shape and adds threshold, interval, value-gated, and rectangle-style
feature families directly inside `GafimeEngine`.

## Highlights

- Added opt-in discrete function search through `EngineConfig`.
- Added candidate-volume controls to `ComputeBudget`.
- Added split-aware discrete candidate ranking so threshold/region candidates
  are not selected by Pearson-only ordering.
- Added native CUDA soft-discrete candidate scoring and selector scoring.
- Added native Metal soft-discrete support where the Metal backend is built.
- Added CPU/NumPy hard discrete mode.
- Added GPU hard-mode rejection with:

  ```text
  GPU feature engineering with discrete hard mode is not supported!
  ```

- Added Rust-side cache-local equation ordering for GPU launch locality.
- Added `from gafime import subfunctions` as the public Rust-helper import.
- Updated tests, benchmarks, docs, skills/context notes, and wheel workflow.

## Usage

```python
from gafime import ComputeBudget, EngineConfig, GafimeEngine

config = EngineConfig(
    metric_names=("mutual_info", "r2"),
    enable_discrete_functions=True,
    discrete_mode="soft",
    discrete_ranking="split_aware",
    budget=ComputeBudget(
        max_discrete_candidates=100_000,
        max_thresholds_per_feature=9,
        max_intervals_per_feature=12,
        max_feature_pairs_for_rectangles=500,
        top_k_features_for_discrete=50,
    ),
)

report = GafimeEngine(config).analyze(X, y, feature_names=feature_names)
```

`metric_names` remains the user's report metric control. There is no separate
discrete metric parameter in v0.4.0. The default discrete ordering is controlled
by `discrete_ranking="split_aware"` and combines mask mutual information,
soft variance reduction, residual absolute correlation, and residual R2 gain.

## Backend Behavior

CUDA/GPU discrete feature engineering uses branchless soft/vectorized math.
Hard threshold mode is intentionally not implemented as a branch-heavy GPU path.

CPU and NumPy may evaluate hard mode using vectorized host comparisons. Metal
soft mode uses GPU-compatible behavior when available; Metal hard mode follows
the GPU hard-mode rejection rule unless a future CPU-side fallback is added.

## Rust Helper Import

Use the package alias in user-facing code:

```python
from gafime import subfunctions
```

The `gafime_cpu` extension name remains an implementation detail.

## Benchmarks And Profiling

Added benchmark/application coverage for:

- continuous-only GAFIME,
- GAFIME with discrete functions,
- sklearn datasets such as California Housing and Friedman1,
- synthetic threshold and rectangle/region datasets,
- optional tree baselines where available.

The CUDA discrete soft-kernel NCU profile after cache-local ordering showed:

- `4.93 ms` launch duration,
- `98.45%` L2 hit rate,
- `3.05%` DRAM throughput,
- `39` registers/thread,
- `0` register spills,
- `100%` branch efficiency,
- `95.30%` achieved occupancy.

## Migration Notes

- Existing continuous interaction workflows remain valid.
- Discrete functions are disabled by default; enable with
  `enable_discrete_functions=True`.
- Prefer `metric_names=("mutual_info", "r2")` or another task-appropriate
  metric set for reporting threshold-heavy signals.
- Use `discrete_ranking="metric"` only when report metrics should also control
  discrete candidate ordering.
- Replace public examples of direct `import gafime_cpu` with
  `from gafime import subfunctions`.
