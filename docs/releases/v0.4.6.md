# GAFIME v0.4.6 Release Notes

v0.4.6 is the Metal validation and native-report integration release. It keeps
the v0.4.5 native execution spine and adds validated Apple Silicon Metal
coverage, clearer platform-aware backend policy, and a deprecation path for
JSON-style report materialization.

## Public API Changes

- `DiagnosticReport` is now backed by a native C++ report table when
  `gafime_core` is available.
- Normal integrations should use live report properties:
  `report.interactions`, `report.stability`, `report.permutations`,
  `report.decision`, `report.backend`, and `report.warnings`.
- `DiagnosticReport.to_dict()` is deprecated. It still works for explicit
  export boundaries, emits `DeprecationWarning`, and materializes a JSON-style
  copy only when called.
- `backend="auto"` now follows a platform-aware native priority list.
- `backend="gpu"` is deprecated because it is ambiguous across platforms.

## Backend Priority Protocol

`backend="auto"` resolves in this order:

| Platform | Priority |
|---|---|
| macOS / Apple Silicon | `metal` -> `core` |
| Linux x86_64 / Windows AMD64 | `cuda` -> `core` |
| Linux ARM64 / Windows ARM64 | `core` |

Explicit impossible requests now fail clearly:

- `backend="cuda"` on macOS raises an unsupported-platform error.
- `backend="metal"` outside macOS raises an unsupported-platform error.
- current ARM Linux and ARM Windows wheels do not expose a CUDA backend.

This means macOS users should choose `backend="auto"` or `backend="metal"` for
GPU execution, not `backend="cuda"`.

## Distribution Workflow

The release tag uses `.github/workflows/build_wheels.yml`.

- Wheel builds target Python 3.10 through 3.14.
- x86 Linux and Windows wheels include CUDA-capable native payloads.
- macOS ARM64 wheels include the Metal payload.
- ARM Linux and ARM Windows wheels package the Rust orchestration layer and C++
  Core CPU backend without NVIDIA CUDA payloads.
- The GitHub release job uses `docs/releases/v0.4.6.md` as its release body.
- PyPI publishing uses the repository Trusted Publisher configuration through
  the `pypi` environment.
