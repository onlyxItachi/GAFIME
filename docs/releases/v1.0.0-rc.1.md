# GAFIME v1.0.0-rc.1

Repository, Cargo, tag, release-note, and GitHub Release identity:
`1.0.0-rc.1` / `v1.0.0-rc.1`. Python runtime, wheel/sdist metadata, and PyPI
identity: `1.0.0rc1`.

This release candidate freezes the supported GAFIME v1 architecture for
real-world soak. It does not promote the project to stable.

## Public Runtime

Python remains the declarative user boundary. Rust owns validation, planning,
scheduling, lifecycle, backend selection, and Core execution; CUDA, ROCm/HIP,
and Metal own their native device execution. The public reference covers the
supported one-shot, resident, compiled, target-update, streaming, significance,
time-series, decision-path, and sklearn surfaces without introducing a new API
for this candidate.

## Precision Profiles

`EngineConfig(precision=...)` exposes three profiles. `fp32` is a genuine lane-wide fp32
path, `mixed` combines binary32 ingest/materialization with binary64
statistics and results, and `fp64` is the end-to-end binary64 route. Core,
CUDA, and ROCm support all three. Embedded Apple Metal supports `fp32` only;
explicit `mixed` or `fp64` Metal requests fail closed.

No precision-specific package or wheel family is introduced.

Production Core scoring distributes independent candidates through Rayon with
worker-local precision scratch and per-candidate SIMD/native arithmetic.
Results are placed and ranked deterministically after parallel execution. The
bounded compiler/codegen audit retained the runtime ISA dispatch and found no
reproducible, semantics-preserving product change that warranted source churn;
this is not a universal performance claim.

## ABI And Distribution

Frozen ABI 1.0 remains byte compatible through thin adapters. ABI 1.1 remains
the canonical generic typed-buffer/numeric-route boundary, with a synthetic
ABI 1.2 fixture preserving forward-compatible record handling. No duplicate
dtype-suffixed full engine is introduced.

The manifest-derived release set uses dedicated CPython 3.10 through 3.14
wheels:

- `gafime` supplies Core wheels and an sdist; macOS arm64 Core wheels alone
  embed the paired Metal dylib and metallib.
- `gafime-cuda` supplies Linux x86_64 and Windows x86_64 payload wheels plus an
  sdist, requires the exact matching Core, and uses the compatible system CUDA
  runtime.
- `gafime-rocm` supplies thin raw Linux x86_64 system-runtime wheels for the
  GitHub Release plus the matching PyPI sdist, and requires the exact matching
  Core.

Windows ARM64 contributes five dedicated wheels, including CPython 3.10,
provisioned from the official `pythonarm64` NuGet packages.

Core has no CUDA or ROCm dependency or extra. There is no standalone Metal
distribution. RT/OptiX remains an experimental local CMake surface and is
excluded from wheels, sdists, workflow artifacts, the frozen bundle, and the
GitHub Release.

## RC Corrections And Documentation

The candidate rejects negative `GafimeSelector.k`, non-positive
`GafimeStreamer.batch_size`, and non-positive `benchmark_streaming.n_batches`
before selection, iteration, or input reads. Regression tests preserve those
fail-fast boundaries.

The root README is the public landing page; `docs/README.md` routes by reader
intent, `docs/releases/README.md` indexes release records, and
`docs/releases/STATUS.md` owns mutable train state. The generated v1 API
reference, public-symbol coverage check, tutorial, operational guide, and
source docstrings remain synchronized with the shipped public API.

## Security And Evidence Boundaries

RC publication is gated on one standard Codex Security repository scan bound
to the exact candidate, validation of any candidate findings, and no unresolved
Critical, High, or release-blocking Medium finding. The prior pre-RC baseline
remains historical evidence. Deep Security Scan is deliberately reserved for
the later RC-to-stable qualification. These reviews are not a claim that
GAFIME is secure or vulnerability-free.

The immutable release workflow binds one reviewed source SHA to checksums,
provenance, package composition, and exact frozen bytes before tagging. Core,
CUDA, ROCm, and Metal execution evidence is recorded according to the release
runbook. Hosted compilation is not represented as physical CUDA or ROCm
execution, and no comparative GPU or universal throughput claim is made.

Release validation and recovery procedures are in
[release-operations.md](release-operations.md).

## Version Identity

GAFIME uses Semantic Versioning for the repository, Cargo, Git tag, release
note, and GitHub Release identity, and the corresponding PEP 440 form for
Python package metadata and PyPI. The release tooling derives one from the
other and rejects ambiguous tag or package spellings.

Historical compact tags and release-note filenames remain immutable. The mixed naming in
`docs/releases/` is intentional historical preservation; new release identities use the
canonical SemVer spelling.

## Deliberate Non-Claims

- Scale-normalized covariance cannot recover an interaction product that
  overflowed before normalization.
- Hosted compilation is not physical CUDA or ROCm execution evidence.
- The standard security scan is bounded qualification, not proof that the
  project is secure or vulnerability-free.
- No universal throughput or comparative GPU performance claim is made.
- RT/OptiX is not a distributed RC1 capability.
