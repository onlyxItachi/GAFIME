# GAFIME v1.0.0a0 Pre-release Readiness Notes

`v1.0.0a0` is a pre-release readiness checkpoint. It has not been tagged,
published, or issued as a release.

## Scope

- Aligns public Python and native boundary version reporting to `1.0.0a0`.
  Cargo uses the equivalent `1.0.0-alpha.0` prerelease form and the native
  module normalizes it for Python users.
- Adds a public capability snapshot and `gafime --check` output that separates
  configured backend, selected backend, runtime probe status, and Core fallback.
- Makes one-shot/resident/compiled execution paths explicit: one-shot stays cache
  disabled, resident runs through the eager resident LRU workflow, and compiled
  runs stay on the explicit compiled session path.
- Hardens compatibility and memory admission:
  optional peak-memory ABIs for CUDA/ROCm/Metal are state-aware, forecast
  retained buffer transitions, and older same-ABI payloads without those queries
  remain explicitly budgeted and fail-closed.
- Reports actual GPU device/graph/optional ABI facts only after the payload's
  C ABI validates. Unprobed or unavailable hardware fields remain `unknown`.
- Separates family generation placement from scoring placement, and includes
  separate significance placement. `time_series` and `decision_path`
  generation remain in `gafime_cpu`; only their subsequent continuous scoring
  can run on CUDA, ROCm, or Metal. Significance placement is reported as a
  family-level `FamilyCapability.significance_support` contract, not split by
  backend.
- Formalizes CPU/GPU/RT algorithmic hardening:
  runtime GPU launch-policy and cache-selection behavior, guarded RT
  grouped-geometry dispatch, and first-hit duplicate-mask correction in RT
  score pathing; production CPU continuous scoring remains one reusable
  interaction vector plus SIMD slice kernels after the fused higher-arity trial
  was benchmarked and rejected.
- Documents that graph capture does not cover generated-family CPU expansion.
- Routes the exact complete-unary CUDA decision-path shape through compact
  Pearson/R2 score rows when an OptiX payload is validated, while preserving the
  established materialized fallback for every unsupported shape.
- Keeps standard CUDA payload policy RT-off by default, and treats optional RT-on
  artifacts (`gafime-cuda-rt` / `gafime_cuda_rt`) as separate optional,
  non-PyPI-distributed artifacts selected with explicit runtime control.
- Captures PR #21 release-only publication hardening: payload-first -> Core ->
  GitHub Release ordering, collision fail-closed behavior with hash-verified
  recovery, serialized publication jobs, alpha GitHub prerelease marking, and
  recovery-only GitHub Release creation that requires the version tag plus all
  three PyPI lanes.
- Refreshes the tracked v1 practice notebook and repository support skills so
  they use only current family, backend, and significance contracts. A release
  gate regenerates the notebook and rejects stale v0.4 discrete guidance.
- Adds a maintainer runbook for publication-disabled validation, normal tag
  sequencing, partial PyPI recovery, and GitHub-Release-only recovery.
- Adds a public version/capability contract for installed-package validation.
- Discovers matching installed `gafime-cuda` and `gafime-rocm` payloads without
  requiring users to set library paths. Explicit environment paths retain
  highest priority and malformed or version-mismatched payloads fail clearly.
- Bundles the native Metal dylib/metallib pair into the macOS arm64 base wheel
  and validates that path through the installed public API on Apple hardware.
- Builds CUDA payloads from all four contracted CUDA source units with OptiX
  disabled by default, while retaining an explicit OptiX-enabled build mode.
- Builds ROCm wheels inside the EL8-based `manylinux_2_28` image and requires
  `auditwheel` inspection and repair before they receive the corresponding
  platform tag.
- Uses one `cp310-abi3` wheel per CUDA/ROCm payload platform instead of
  rebuilding an identical native payload for every Python minor version.
- Separates Core, CUDA, and ROCm validation/source-distribution dependencies so
  one vendor lane cannot suppress another lane's manually approved PyPI job;
  the GitHub Release gate still requires the complete artifact set.
- Compiles distributed CUDA and ROCm payloads at `-O3` without enabling any
  math-relaxing flags.

## Deliberate Non-Claims

- No CUDA, ROCm, or Metal generated-family kernel is claimed.
- No RT support is inferred from a device name, environment variable, or an
  unvalidated payload.
- CUDA, ROCm, and Metal permutation maxT uses bounded same-device ranking when
  the payload advertises it. CUDA may use its optional native fixed-plan
  p-value ABI; bootstrap stability remains a selected-candidate CPU pass.
- Arrow ingestion is not described as zero-copy into GAFIME compute memory.

## Evidence Boundaries

- Compile coverage in this checkpoint captures source and boundary-layer
  hardening: staged package policy, modular Rust boundary extraction, modular
  release tests, and RT artifact policy wiring in the prerelease.
- Runtime evidence in this checkpoint is recorded for local `sm89` CUDA and local
  `gfx1150` ROCm; hosted runtime gates include Apple Metal on macOS. Other
  packaged architectures are represented as compile coverage for this
  prerelease.
- Optional OptiX remains separate from the standard bundle (`gafime-cuda-rt`,
  non-PyPI), with explicit selection and separate artifact policy.

## Remaining Release Gates

This checkpoint does not replace final-current-commit hardware validation.
Before any release decision, run the full wheel workflow with publication
disabled, the native-platform workflow, installed-wheel contracts, and the
applicable CUDA, ROCm, and Metal parity gates. If the optional OptiX artifact is
produced, its separate hardware lane must pass; it does not gate the standard
RT-off release bundle. No tag or publication is part of this work.

The exact dry-run and recovery commands are maintained in
[`release-operations.md`](release-operations.md). Recovery inputs are not normal
release settings and must never be enabled preemptively.
