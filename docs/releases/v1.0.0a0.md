# GAFIME v1.0.0a0 Pre-release Readiness Notes

`v1.0.0a0` is a pre-release readiness checkpoint. It has not been tagged,
published, or issued as a release.

## Scope

- Aligns public Python and native boundary version reporting to `1.0.0a0`.
  Cargo uses the equivalent `1.0.0-alpha.0` prerelease form and the native
  module normalizes it for Python users.
- Adds a public capability snapshot and `gafime --check` output that separates
  configured backend, selected backend, runtime probe status, and Core fallback.
- Reports actual GPU device/graph/optional ABI facts only after the payload's
  C ABI validates. Unprobed or unavailable hardware fields remain `unknown`.
- Separates family generation placement from scoring placement. `time_series`
  and `decision_path` generation remain in `gafime_cpu`; only their subsequent
  continuous scoring can run on CUDA, ROCm, or Metal.
- Documents that graph capture does not cover generated-family CPU expansion.
- Adds a public version/capability contract for installed-package validation.
- Discovers matching installed `gafime-cuda` and `gafime-rocm` payloads without
  requiring users to set library paths. Explicit environment paths retain
  highest priority and malformed or version-mismatched payloads fail clearly.
- Bundles the native Metal dylib/metallib pair into the macOS arm64 base wheel
  and validates that path through the installed public API on Apple hardware.
- Builds CUDA payloads from all four contracted CUDA source units with OptiX
  disabled by default, while retaining an explicit OptiX-enabled build mode.
- Builds ROCm wheels inside the EL8-based `manylinux_2_28` image and requires
  `auditwheel` inspection and repair before they receive the corresponding
  platform tag.
- Uses one `cp310-abi3` wheel per CUDA/ROCm payload platform instead of
  rebuilding an identical native payload for every Python minor version.
- Separates Core, CUDA, and ROCm validation/source-distribution dependencies so
  one vendor lane cannot suppress another lane's manually approved PyPI job;
  the GitHub Release gate still requires the complete artifact set.
- Compiles distributed CUDA and ROCm payloads at `-O3` without enabling any
  math-relaxing flags.

## Deliberate Non-Claims

- No CUDA, ROCm, or Metal generated-family kernel is claimed.
- No RT support is inferred from a device name, environment variable, or an
  unvalidated payload.
- No GPU device-significance path is claimed outside the optional CUDA
  permutation-pvalues ABI and its eligibility conditions.
- Arrow ingestion is not described as zero-copy into GAFIME compute memory.

## Remaining Release Gates

This checkpoint does not replace backend hardware validation. Before any
release decision, run the full wheel workflow with publication disabled, the
native platform workflow, installed-wheel contracts, and the applicable
hardware parity gates for CUDA, ROCm, and Metal. OptiX-enabled CUDA and real
ROCm runtime execution remain explicit hardware gates. No tag or publication
is part of this work.
