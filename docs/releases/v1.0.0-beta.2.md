# GAFIME v1.0.0-beta.2

Repository, Cargo, tag, release-note, and GitHub Release identity:
`v1.0.0-beta.2`. Python package and PyPI identity: `1.0.0b2`. These are two
standards-compliant representations of the same release.

## Runtime And Numerical Hardening

- Interaction-materialization diagnostics now report finite-input overflow
  separately from source non-finite rows across Core, CUDA, ROCm, and Metal.
- Resident execution reuses diagnostics only for the exact matrix shape and
  content epoch; changed inputs invalidate the cached observation.
- CPU covariance combines finite checks with the main SIMD reduction while
  preserving early rejection for non-finite inputs.
- The AVX2 fixed-bin MI index path uses a branchless conversion where its exact
  scalar-equivalence preconditions hold and retains the scalar fallback
  elsewhere.
- Production unsafe invariants and workspace Clippy warnings are enforced as
  release gates.

## Distribution

The standard bundle contains 11 artifacts across three Python distributions:

- `gafime`: five `cp310-abi3` platform wheels plus one sdist. The macOS arm64
  wheel alone embeds the paired Metal dylib and metallib.
- `gafime-cuda`: Linux x86_64 and Windows x86_64 wheels plus one sdist, with
  the standard RT-off policy.
- `gafime-rocm`: one thin `linux_x86_64` system-runtime wheel for the GitHub
  Release plus one PyPI sdist.

The same Stable ABI wheel is executed on Python 3.10 through 3.14 wherever a
native hosted interpreter exists. Windows ARM64 has the documented 3.11-3.14
hosted-runtime boundary.

The release manifest, workflow graph, generated artifact matrix, optional
extras, archive composition, and publication selection are checked as one
contract. A separate Metal distribution or publisher fails that contract.

## Version Identity

GAFIME now permanently uses the native standard of each release surface:
Semantic Versioning (SemVer) for repository identity and PEP 440 for Python
distribution identity.

| Surface | Identity |
|---|---|
| Cargo, Git tag, GitHub Release, changelog, release note | `1.0.0-beta.2` / `v1.0.0-beta.2` |
| Python runtime, wheel/sdist metadata, PyPI | `1.0.0b2` |

The strict release parser derives the PEP 440 identity from SemVer, rejects
unsupported or ambiguous public identifiers, validates all source and frozen
artifact metadata, and classifies prereleases structurally rather than by
substring matching.

Historical compact tags and release-note filenames such as `v1.0.0b0`,
`v1.0.0b1`, and `v1.0.0b1.md` remain unchanged. The mixed naming in
`docs/releases/` is intentional historical preservation; every new release
record follows the strict SemVer naming above.

## Evidence Boundaries

- Cross-backend parity demonstrates agreement with the selected Core
  reference path; it is not independent proof that shared arithmetic cannot
  overflow.
- Hosted compilation is not physical-device runtime evidence. CUDA sm89, ROCm
  gfx1150, and hosted Apple Metal evidence remain separately identified.
- The ROCm clean-install smoke proves its pinned external userspace closure; it
  does not prove arbitrary ROCm installations are interchangeable.
- CPU kernel performance evidence is shape- and host-specific. No universal
  end-to-end speedup is claimed.

## Deliberate Non-Claims

- Scale-normalized covariance cannot recover an interaction product that
  overflowed before normalization.
- Overflow diagnostics identify affected rows; they do not silently repair or
  reinterpret those interactions.
- The standard CUDA payload remains RT-off. OptiX artifacts are separately
  selected and are not part of the standard bundle.
- The thin ROCm wheel is not manylinux and is not uploaded to PyPI.
