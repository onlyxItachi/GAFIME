# GAFIME v1.0.0 — Stable Runtime Stabilization

Repository/Cargo and Python/PyPI identity: `1.0.0`; canonical Git/GitHub tag:
`v1.0.0`. Semantic Versioning and PEP 440 agree for this stable identity.
Production/Stable package classification identifies the intended release line,
not completed publication, security review, or artifact qualification. Follow
[STATUS.md](STATUS.md) and the [release operations runbook](release-operations.md)
for exact-candidate qualification requirements and live publication channels.

## Bounded Stabilization Since RC2

- [File ingest](../ingest-validation.md) preserves wide source values until
  Rust's checked conversion, keeps source NaN/Inf semantics, and forwards the
  complete planning seed. Raw Arrow dtype and configuration admission remain
  strict; unsupported shortcuts take the existing configured validation path.
- [Adaptive time-series significance](../adaptive-time-series.md) repeats
  source selection and expansion for every permuted target. Compiled target
  updates/reseeds refresh generated metadata; inconsistent post-update state
  retires the artifact rather than exposing stale reports or names.
- Rust rejects invalid threshold and count configurations consistently, with
  finite non-negative thresholds checked in the selected result lane.
- [Native CUDA/HIP coordination](../gpu-execution-coordination.md) serializes
  ordinary ABI 1.0 and ABI 1.1 calls per loaded payload through cleanup and
  caller-device restoration. The opt-in qualification runner requires bounded,
  run-bound completion and per-worker timed participation for both ABI routes.

These changes retain the top-level public API, thread-affinity and ownership contracts,
backend selection, and numerical profiles. ABI 1.0 remains frozen; ABI 1.1
remains the generic typed-buffer/numeric-route boundary. No GIL-release,
TLS/cache, Rayon-topology, or shutdown redesign is included.

## Precision Profiles

`EngineConfig(precision=...)` remains the sole precision selector: `fp32` is
genuine lane-wide fp32; default `mixed` uses fp32 storage/pointwise arithmetic
with fp64 statistics/results; `fp64` remains fp64 end to end. Core, CUDA and
ROCm carry all three profiles. Embedded Apple Silicon Metal supports fp32 only
and fails closed for explicit mixed/fp64 requests. No precision-specific package
or wheel family is added.

## Distribution And Qualification

The standard distributions remain Core `gafime`, RT-disabled `gafime-cuda`,
and thin/system-runtime `gafime-rocm`. Core has no vendor-payload dependency;
payloads require exactly matching Core. Metal is embedded in macOS arm64 Core.
Dedicated CPython 3.10–3.14 artifacts remain manifest-derived.
Windows ARM64 contributes dedicated CPython 3.10–3.14 wheels under the manifest,
including CPython 3.10, provisioned from the official `pythonarm64` NuGet packages.
ROCm's raw Linux wheels remain on
GitHub Releases and its matching source distribution on PyPI.

Source preparation and local regression/physical candidate evidence do not
qualify the final stable artifacts. Current-head review, hosted correctness
checks, and final exact-candidate deep Codex Security qualification precede the
final build and frozen-bundle provenance/composition/checksum verification.
Required physical backend execution then uses exact members of that verified
frozen bundle before unchanged-tip admission, tag protection, and ordered
publication. These remain separate gates. Prior security
records apply to their original checkpoints; detailed findings remain private.

Historical compact tags and release records are unchanged. The mixed naming
in `docs/releases/` is intentional historical preservation, not permission to
use legacy spellings for new versions.

## Deliberate Non-Claims

- Normalization cannot recover a product that overflowed before normalization.
- A private input snapshot is not atomic against external writers.
- A native payload gate does not own caller handle/buffer lifetimes or
  coordinate separately loaded payloads, foreign frameworks, or RT entry points.
- Timed caller participation does not prove device utilization or all possible
  driver interleavings; hosted compilation is not physical backend execution.
- No vulnerability-free guarantee, completed final security gate, universal
  throughput, or comparative GPU performance claim is made.
- Experimental RT/OptiX and the future low-copy input protocol are not shipped
  stable capabilities.
