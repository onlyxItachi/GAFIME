# GAFIME v1.0.0 — Unreleased Stable Preparation

Planned repository/Cargo and Python/PyPI identity: `1.0.0`; planned canonical
Git/GitHub tag: `v1.0.0`. Semantic Versioning and PEP 440 agree for that target.
These mainline pruning changes do not bump source versions, create a candidate
branch or authorize stable qualification/publication. RC3's published source,
tag, packages and evidence remain immutable. See [release operations](release-operations.md).

## Removed V0.x Configuration Compatibility

- `EngineConfig` and `backend_capabilities` no longer accept
  `storage_dtype`/`compute_policy` keyword pairs or map them to a precision.
- `enable_discrete_functions` is rejected, including the former no-op false
  value. No removed discrete family is restored.
- Historical positional constructor layouts are no longer translated. The
  canonical first ten `EngineConfig` fields through `device_id` and first six
  `ComputeBudget` fields retain their order; later fields remain keyword-only.

This intentionally breaks obsolete v0.x source compatibility between RC3 and
stable preparation, not active v1 numerical behavior. Requested profiles,
backend selection, candidate order/identity and the Rust execution contract
remain unchanged. `max_generated_features` is retained pending a separate
public-contract decision, not repurposed as a generated-family limit.

## Removed Compiled Compatibility Projection

`CompileFlags.plan`, `scenario_plan`, the `gafime.compile.scenario` projection,
and the deprecated `exports`/`gafime.compile.exports` handle view are removed.
Compile flags are keyword-only; old positional flag calls are rejected rather
than reinterpreted. Native planning remains Rust-owned. `CompiledGafime` and
`from_engine` remain available, as do graph requests, compiled lifecycle and
`export_arrow()`/`__arrow_c_array__()` with native result release callbacks.
Arrow result export is separate from Arrow input ingestion.

## Maintained Helpers And Removed Scheduler Utilities

The intentional `gafime.subfunctions` namespace remains lazy and uses an explicit
export list. Retired BatchScheduler, CacheAwareScheduler and SmartScheduler
implementations/registrations and obsolete `gafime_cpu` lookup paths are removed;
the authoritative v1 Rust planner and scheduler are not replaced.

DataQualityAnalyzer retains its current behavior with `DeprecationWarning` on
construction. Future replacement belongs to the Polars migration (#87) for
v1.1/v1.2 and will be caller-opt-in: no silent cleaning, feature deletion or
mutation. Polars remains below 2. OTSEncoder remains unchanged; backend-neutral
integration is deferred to issue #119, not implemented here. See the
[pruning and retained-API disposition](../legacy-pruning.md).

## Planner RNG Naming, Not Replacement

The active private `legacy_rng.rs` module is renamed to `cpython_mt19937.rs`.
Its algorithm, seed-word interpretation, stream consumption and shuffle order
are unchanged. Existing candidate-order goldens are retained, with an additional
wide-seed/repeated-shuffle CPython oracle. No new RNG dependency is introduced;
see [planner randomness](../cpython-mt19937-planning.md).

Final stable identity, exact-source review/security qualification, installed
correctness and performance gates, a new frozen stable artifact set and
physical/runtime qualification remain future separately authorized work.
No RC4, stable tag, release freeze or publication is implied.
