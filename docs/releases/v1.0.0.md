# GAFIME v1.0.0 — Stable Source Preparation

Prepared repository/Cargo and Python/PyPI identity: `1.0.0`; future canonical
Git/GitHub tag: `v1.0.0`. Semantic Versioning and PEP 440 agree for that target.
Production/Stable metadata describes the intended release line, not completed
qualification or publication. Source preparation does not itself create a
candidate branch or authorize final qualification/publication. RC3's published
source, tag, packages and evidence remain immutable. See
[STATUS.md](STATUS.md), [source integration](stable-integration.md) and
[release operations](release-operations.md).

## Retained V1 Architecture And RC3 Hardening

Python remains the public declaration/reporting boundary. Rust owns validation,
planning, scheduling, backend selection and lifecycle. Core retains
candidate-level Rayon execution with worker-local scratch and per-candidate
SIMD; CUDA, ROCm/HIP and Metal retain their native execution. ABI 1.0 remains
frozen compatibility; additive ABI 1.1 retains generic typed buffers and numeric
routes. Candidate identities/order, equations and precision tolerances do not
change in this source preparation.

Ordinary numeric `dataload` uses incremental Arrow C Streams and checked
Rust-owned acquisition with the full existing configuration. Multiple batches
and differently chunked feature/target streams retain alignment. Foreign
owners release after acquisition and before resident compilation; finite fp32
overflow is rejected before narrowing without conflating it with source
NaN/Inf. Seeds, literal column names and candidate-cap warnings stay preserved.
See [ingest validation](../ingest-validation.md).

Adaptive time-series selection repeats for permutations and compiled target
updates/reseeds. Committed generated-family rebuild failures retire inconsistent
state. The CUDA/HIP per-loaded-payload gate covers ordinary exported entry
points, not foreign frameworks, separately loaded payloads or caller handle
lifetime. No GIL detachment or concurrency architecture is introduced.

RC3's parser-aware RSS controls, latency/numerical gates, copy/lifetime ledger
and complete allocator/THP/thread provenance remain intact. So do the reviewed
Core calibration-headroom and macOS CI Rustup fixes. Stable tag tests accept
stable SemVer/PEP 440 equality without accepting compact prerelease Git tags.

## Precision Profiles

`EngineConfig(precision=...)` remains the sole profile selector. `fp32` is
genuine lane-wide fp32 across storage,
pointwise work, statistics and public results; default `mixed` uses fp32
storage/pointwise work and fp64 statistics/results; `fp64` is fp64 throughout.
Core, CUDA and ROCm support all three profiles. Embedded Apple Silicon Metal
supports fp32 only; explicit mixed/fp64 requests fail closed.
No precision-specific package or wheel family is introduced.

## Distribution

Core `gafime` has no vendor-payload dependency. RT-disabled `gafime-cuda` and
thin/system-runtime `gafime-rocm` depend on exactly matching Core. CUDA uses
its system runtime; ROCm raw Linux wheels belong on GitHub Releases and the
matching sdist on PyPI. Metal is embedded only in macOS arm64 Core, not a
standalone distribution. Dedicated CPython 3.10–3.14 and platform composition
remain governed by the unchanged [artifact matrix](release-artifact-matrix.md).
Windows ARM64 contributes five dedicated wheels, including CPython 3.10,
provisioned from official `pythonarm64` NuGet packages. No abi3 is restored.

## Removed V0.x Configuration Compatibility

- `EngineConfig` and `backend_capabilities` no longer accept
  `storage_dtype`/`compute_policy` keyword pairs or map them to a precision.
- `enable_discrete_functions` is rejected, including the former no-op false
  value. No removed discrete family is restored.
- Historical positional constructor layouts are no longer translated. The
  canonical first ten `EngineConfig` fields through `device_id` and first six
  `ComputeBudget` fields retain their order; later fields remain keyword-only.

This intentionally breaks obsolete v0.x source compatibility between RC3 and
stable preparation, not active v1 numerical behavior. Requested profiles,
backend selection, candidate order/identity and the Rust execution contract
remain unchanged. `max_generated_features` is retained pending a separate
public-contract decision, not repurposed as a generated-family limit.

## Removed Compiled Compatibility Projection

`CompileFlags.plan`, `scenario_plan`, the `gafime.compile.scenario` projection,
and the deprecated `exports`/`gafime.compile.exports` handle view are removed.
Compile flags are keyword-only; old positional flag calls are rejected rather
than reinterpreted. Native planning remains Rust-owned. `CompiledGafime` and
`from_engine` remain available, as do graph requests, compiled lifecycle and
`export_arrow()`/`__arrow_c_array__()` with native result release callbacks.
Arrow result export is separate from Arrow input ingestion.

## Maintained Helpers And Removed Scheduler Utilities

The intentional `gafime.subfunctions` namespace remains lazy and uses an explicit
export list. Retired BatchScheduler, CacheAwareScheduler and SmartScheduler
implementations/registrations and obsolete `gafime_cpu` lookup paths are removed;
the authoritative v1 Rust planner and scheduler are not replaced.

DataQualityAnalyzer retains its current behavior with `DeprecationWarning` on
construction. Future replacement belongs to the Polars migration (#87) for
v1.1/v1.2 and will be caller-opt-in: no silent cleaning, feature deletion or
mutation. Polars remains below 2. OTSEncoder remains unchanged; backend-neutral
integration is deferred to issue #119, not implemented here. See the
[pruning and retained-API disposition](../legacy-pruning.md).

## Planner RNG Naming, Not Replacement

The active private `legacy_rng.rs` module is renamed to `cpython_mt19937.rs`.
Its algorithm, seed-word interpretation, stream consumption and shuffle order
are unchanged. Existing candidate-order goldens are retained, with an additional
wide-seed/repeated-shuffle CPython oracle. No new RNG dependency is introduced;
see [planner randomness](../cpython-mt19937-planning.md).

## Deliberate Non-Claims

Final exact-source review/deep security qualification, installed
correctness and performance gates, a new frozen stable artifact set and
physical/runtime qualification remain future separately authorized work.
No RC4, stable tag, release freeze or publication is implied.

Earlier scans, benchmarks and physical runs retain their original source,
artifact, hardware and disclosed limitations; they are not silently relabeled
as final stable qualification. Analysis holds the GIL and Ctrl-C waits for
native return. An owned snapshot is not atomic against external writers;
resident layout conversion and device upload can require additional copies.
Normalization cannot recover a product that overflowed before normalization.

No universal performance claim or security guarantee is made. RT/OptiX stays
local-only and excluded from standard artifacts. Polars 2, broader borrowing
and future feature architecture remain separate work. A dedicated v0.x-to-v1
migration notebook remains pending; the pre-v1 full API notebook stays
historical. Historical compact tags and the mixed naming in `docs/releases/`
remain intentional historical preservation, not canonical spelling for new tags.
